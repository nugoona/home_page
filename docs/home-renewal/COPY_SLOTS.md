## S2 공통 철학

> 현행 `Philosophy.tsx`의 장문 3막(opening + acts[3]{title, lines[]})을 **해체**하고, 공통 철학만 **짧은 선언**으로 남긴다. 제품 목업 배치 안 함.

- **eyebrow/라벨**: `OPTIONAL`(예: "왜 만들었나").
- **헤드 슬롯**: `REQUIRED`. 메시지 = "전문가만의 일이었던 마케팅의 진입장벽을 낮춘다". ⚠️ 현행 opening `누구나 마케팅하는 시대…`는 **H1과 중복이라 `REMOVE`** — 새 헤드로 교체.
- **선언 본문 슬롯**: `REQUIRED`. 1~3개의 짧은 문장(진입장벽=계정·용어·설정·운영 / 앱은 준비·이해를 돕고 결정은 고객이). 장문 서술 지양.
- **현행 3막 title·lines**: `REMOVE`(해체). 단 문장 일부는 S3/S4 제품 철학 재료로 이전 가능(카피는 ChatGPT 결정).
- **허용 줄 수**: 헤드 1~2줄 / 본문 문장당 1~2줄, 총 2~4문장.
- **PC/모바일 권장 글자 수**: 헤드 ≤20자, 본문 각 문장 ≤32자(PC)/≤20자(모바일).
- **현재 컴포넌트 파일**: `nugoona/components/home/Philosophy.tsx`.
- **현재 데이터 출처**: `home.ts` → `philosophy`(opening·acts[3]).

**새 섹션 판단(구현 아님 — 근거만)**
- **기존 Philosophy 재구성 가능한가**: 가능. 현행이 `opening`(중앙 헤드) + `acts.map`(막 반복)이라, `acts`를 짧은 선언 배열로 축소하고 `MOCKS` 맵(목업 바인딩)을 제거하면 "짧은 선언" 섹션으로 재구성된다.
- **새 컴포넌트 필요한가**: 필수는 아님. 다만 철학을 S2(공통)·S3(콘텐츠)·S4(광고)로 3분할하므로, 공통 철학 전용 경량 컴포넌트로 분리하는 편이 각 섹션 독립성에 유리(판단 = Phase 4).
- **판단 근거**: `Philosophy.tsx`는 `philosophy` 데이터와 `PhilosophyMocks`에 강결합. 목업을 떼면 S2용으로 가볍게 재사용 가능하나, 제품 목업이 S3/S4로 가므로 결합을 끊는 리팩터가 동반됨.

- **서브 문단 수**: 현행 3문단(`promise.sub[3]`). `REQUIRED` 1~3문단. ⚠️ 현행 sub[2] `…나머지는 누구나 콘텐츠가 하겠습니다.` = **주어 콘텐츠 한정 → 두 제품 공통 주어로 교체**(§5-5).

- **타임라인 사용 여부 결정 대기 항목**: `promise.log`(8건, 2025.12~2026.07) = **가상 날짜**. PM 지시로 **확정 보류** — 표시 방식(실제 날짜 검증 / 날짜 제거 / 타임라인 대체) = "카피/시각물 결정 대기". 부연 문장 `한 번 시작한 요금 그대로<br>끝까지 무료 업데이트를 진행합니다.<br>매체가 변하면 콘텐츠도 변해야 합니다.` 는 하드코딩(`PromiseTimeline.tsx`), 주어 점검 대상.
- **반복 표현 주의**: "추가 비용/요금 없음"이 현재 sub[1]·강조·부연 3회 → 강조 1곳 + 최소 부연으로.
- **공통 주어 규칙**: 두 제품 공통 약속이므로 주어는 회사/두 제품(콘텐츠 단독 금지).
