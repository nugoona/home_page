# 누구나컴퍼니 홈 개편 PM 인수인계

> **문서 지위**: 이 문서는 홈 개편에 한해 기존 정본(`nugoona/DESIGN.md`·`CONTENT.md`·`DEPLOY.md`)보다 **상위**다(사장님 확정 2026-07-13). PM(ChatGPT)이 브랜드·UX·카피를 결정하고, 실행(Claude Code)이 조사·구현·검증을 맡는 협업 체계의 단일 소스. 기존 정본은 여기 결정에 맞춰 점진 이관한다.
> **작성 기준**: 아래 내용은 전부 **현재 실제 코드**를 직접 읽어 기록했다(조사 요약이 아니라 코드 우선). 조사 요약과 어긋난 지점은 §5에 "조사 vs 코드 차이"로 명시했다.
> **미수정 원칙**: 이번 작업에서 홈 코드·카피 데이터·이미지·스타일은 **하나도 수정하지 않았다**(문서 2건만 생성).

## 1. 프로젝트 목표

누구나컴퍼니는 **검색 노출과 온라인 광고를 사장님이 직접 운영하도록 돕는** 두 제품을 만든다.

- **누구나 콘텐츠** — 마케팅에 시간을 쓰기 어려운 스토어·서비스업 사장님 대상. 사진·메모를 올리면 켜진 채널별로 글을 생성해 검토 후 발행, 목표 키워드·1년치 글감 제안, 검색 위치를 정직하게 측정·표시. 발행 자산은 사장님 본인 계정에 남는다.
- **누구나 광고** — 광고가 필수인 이커머스 셀러·브랜드 대상. AdCanvas로 소재 제작, 광고·매출·유입을 한 화면에서 확인, 쉬운 말로 묻는 AI 챗봇, 월간 리포트·트렌드 페이지. 계정 연결은 운영자가 도와주는 매니지드 온보딩.

**이번 개편의 목적** = 현재 홈(S1~S5)이 (a)광고 제품의 이유·철학을 거의 못 드러내고 (b)철학이 콘텐츠에 치우쳐 있으며 (c)히어로 서브가 H1을 반복할 뿐이고 (d)기능이 회사의 이유보다 먼저 나오는 문제를 구조부터 다시 잡는 것. 이 문서는 그 재설계를 위한 기준·근거·의사결정 항목을 정리한다.

## 2. 확정된 브랜드 원칙

### 공통 철학
- 마케팅을 전문가만의 일로 두지 않는다.
- 어려운 계정 구조·용어·설정의 진입장벽을 낮춘다.
- 고객의 상품·서비스는 고객이 가장 잘 안다. 앱은 준비와 이해를 돕고, **결정은 고객이** 한다.
- 종속시키기보다 스스로 운영할 수 있게 한다.
- 기능의 핵심은 "쉽다"보다 **"불필요한 고민을 줄인다"**에 가깝다.
- 결과를 과장하거나 성과를 약속하지 않는다.
- 매체·알고리즘 변화는 앱에 계속 반영하고, **기존 고객에게 업데이트 추가 비용을 받지 않는다.**

### 고객
- 콘텐츠 = 마케팅에 시간을 쓰기 어려운 스토어·서비스업 사장님.
- 광고 = 광고가 필수인 이커머스 셀러·브랜드.

### 절대 금지 표현 (홈 카피·목업 전부)
1. 순위·상위노출·매출·조회수·ROAS **개선/보장**. (측정·현황 표시는 허용 — "3페이지 27위"·"아직 안 보임" 같은 정직한 표기)
2. "6곳 발행"처럼 현재 라이브 범위를 넘는 **채널 수 단정.**
3. **셀프 원클릭 계정 연동** 표현. (실제 = 운영자가 도와주는 매니지드 온보딩)
4. AI가 **무엇이든 상담**하거나 모든 광고 변경을 수행한다는 표현.
5. **대행사 비난.**
6. **소상공인·영세** 등 표현을 홈 카피에 직접 사용.
7. **미출시 기능**을 현재 제공 기능처럼 표현.
8. (프로젝트 누적) 파스텔·AI 슬롭 미감, Vercel/Linear 회색 미니멀 문법의 직접 이식, AI 모델명(예: Gemini) 노출.

### 사실 가드레일 (측정·매니지드·현재형)
- 노출은 **올려주는** 게 아니라 **측정·표시하고 하락을 경고**한다.
- 광고 성과는 **쉬운 말로 설명**한다(예: "1만 원당 3.2명이 장바구니에 담았어요") — 과거 사실 서술이지 미래 보장이 아니다.
- 제품명 공식 표기 = **"누구나 콘텐츠" / "누구나 광고"**. NGN = 로고·영문 표기 전용(제품명에 쓰지 않음). 목업 내부 영문 UI(NGN Dashboard·app.ngn.co.kr 등)는 유지.

## 5. 확인된 문제 (코드·렌더 근거)

### 5-1. S2 카피 정본 불일치 (조사 vs 코드 차이 — 코드 우선)
`home.ts`의 `branch` export(카드 title "검색하면 우리 가게가 먼저 보였으면 좋겠습니다" 등)는 **실제 렌더에 쓰이지 않는다.** `PhoneScene.tsx`·`AdScene.tsx`는 `branch`를 import하지 않고 카피를 **하드코딩**한다. 즉 화면 문구("검색에 보이고 싶습니다")와 데이터 파일의 `branch`가 서로 다른 문장이며, `branch`는 구 `ProductBranch`(폐기) 잔재다. → 카피를 고칠 때 **`home.ts branch`가 아니라 두 Scene 컴포넌트를 직접** 고쳐야 한다.

### 5-2. 철학(S3)이 콘텐츠 제품에 치우침 (코드 확인)
`philosophy.acts` 3막 전부 콘텐츠(검색 노출) 언어다.
- 1막 "마케팅은 늘 남의 일이었습니다" — 상위 노출 광고비·검색 상단.
- 2막 "그런데 규칙이 바뀌었습니다" — 포털 검색·방문/리뷰/판매·직접 운영.
- 3막 "그래서, 직접 할 수 있게 만들었습니다" — 키워드 검색결과 노출·SNS 계정.

광고 제품의 탄생 이유·철학을 담은 문장은 **본문에 0개**이고, 광고는 3막의 `AdChatMock`(시각물)로만 거든다. → 광고 철학의 부재가 이번 개편의 핵심 과제.

### 5-3. 히어로 서브가 H1 반복 (코드 확인)
H1 "누구나 마케팅하는 시대" ↔ sub "어려운 마케팅, 이제는 누구나 쉽게 할 수 있습니다." — 두 제품·고객 가치·구체적 무엇을 설명하지 않고 H1을 풀어 쓴 수준. 또한 **S3 opening도 "누구나 마케팅하는 시대"로 H1을 재차 반복**한다.

### 5-4. 광고 대시보드 이미지 내부 날짜 불일치 (렌더 관찰)
`app-dashboard-mobile.jpg` 안에서 **헤더 "최종 업데이트 3월 11일"과 순매출 카드 "7월 12일"이 서로 다르다.** 실제 앱 스샷이라 교체 시 재캡처가 필요(§8).

### 5-5. S4 공통 약속의 주어가 콘텐츠로 한정 (코드 확인)
S4는 두 제품 공통 약속인데 `promise.sub[2]` = "나머지는 **누구나 콘텐츠가** 하겠습니다." 로 주어가 콘텐츠에 한정된다. 타임라인 log는 콘텐츠 4·광고 4로 균형이나 마무리 문장 주어가 어긋난다.

### 5-6. 반복 문구 (코드 확인)
- "무료로 시작하기" = S1 히어로 CTA + S5 primary 버튼, 2회.
- "추가 비용/추가 요금 없음" = S4 sub[1] + S4 마무리 강조 + S4 부연, 3회.
- "카드 필요 없음/약정 없음" = S5 title + S5 sub, 반복.

### 5-7. 기능이 이유보다 먼저 (구조 확인)
현재 순서 S1→S2(제품 기능 분기)→S3(왜 만들었나). 회사의 이유(철학)가 제품 기능 뒤에 온다.

### 5-8. home.ts 폐기 레거시 대량 (코드 확인)
`home.ts`에는 홈에서 **실제로 쓰이지 않는** export가 다수 남아 있다: `branch`, `exposure`, `painPoints`, `solution`, `evidence`, `features`, `comparison`, `reviews`, `faqItems`. 홈 실사용 = `hero`·`philosophy`·`promise`·`cta` 4개 + S2 하드코딩. → 카피 슬롯을 잡을 때 어느 export가 살아있는지 혼동 주의(이 표가 근거).

## 7. 구현 제약 (섹션 순서·이동·카피·반응형)

1. **섹션 순서·컴포넌트 이동**: `page.tsx`에서 `<Section>` 블록 순서만 바꾸면 재배치는 쉽다. 단 각 `<Section>`의 `noBorder`/`alt` 플래그와 **다크/라이트 연속**을 함께 조정해야 한다(현재 S4 다크→S5 라이트 `#fafafa`로 전환해 다크 연속을 피함 — 순서가 바뀌면 이 대비를 다시 설계).
2. **S2 카피 위치**: 두 Scene은 `home.ts`를 참조하지 않고 **하드코딩**이라, 카피 변경은 `PhoneScene.tsx`·`AdScene.tsx` 안에서 직접. (여타 섹션은 `home.ts` 데이터만 고치면 됨)
3. **줄바꿈 규칙**: 모든 서브/본문 카피는 `<br>`을 데이터에 직접 넣고 `dangerouslySetInnerHTML`로 렌더한다(순수 텍스트 → HTML). 헤드=`text-wrap:balance`, 본문=`pretty` 전역(globals.css @layer base). PC/모바일 폰트 크기는 `text-[16px] max-md:text-[14px]` 패턴, 자간 `-0.01em`, 행간 `1.5~1.55`(사장님 확정: 서브는 촘촘하게).
4. **정렬 규칙**(사장님): 텍스트는 **왼쪽 정렬 + 블록 자체를 중앙**(`mx-auto`/`items-center`). `text-center`로 문장 가운데 정렬 금지(단 S3 opening 제목만 예외적으로 text-center).
5. **철학 목업 레이아웃 의존성**: `Philosophy.tsx`의 `MOCKS` 맵이 **막 인덱스(0/1/2)에 목업을 하드 바인딩**한다(1→RankMock right, 2→AdChatMock below). 막을 늘리거나 순서를 바꾸면 이 인덱스 매핑을 함께 고쳐야 한다. `side: 'right'`는 지그재그(`flex`), `'below'`는 세로 중앙(채팅 UI가 길어서), `null`은 목업 없음.
6. **S2 반응형**: PC=phone-frame(z2)+스샷(z1, 화면영역 %좌표 `SCREEN` 상수), 모바일=프레임 없이 스샷 1px 박스. `min-w-0`로 그리드 오버플로 방지. 검은 테두리는 `md:hidden`(모바일만) — PC엔 적용 안 됨.
7. **S5 CTA 버튼**: 데스크톱 가로 배열(`justify-start`), `max-sm`(모바일)에서 세로 스택(`max-sm:flex-col max-sm:items-stretch`), secondary는 모바일 `w-full max-w-[320px]`.
8. **모션**: `FadeUp`은 whileInView 기반. 홈 fullPage 캡처 시 발화 안 되는 함정 있음(§8 검증). 섹션 이동해도 FadeUp은 재사용 가능.
9. **레거시 보존 규칙**(DESIGN §8.6): 폐기 컴포넌트(HeroAurora·ProductBranch 등) 원작은 삭제하지 않고 보존 중. `home.ts`의 폐기 export도 함부로 지우지 말 것(다른 라우트가 참조할 수 있음 — 확인 후 정리).

## 8. 검증이 필요한 사실 (코드·자료만으로 미확정)

1. **앱 스크린샷의 정확한 빌드·캡처 계정** — `app-home-mobile.jpg`(누구나컴퍼니님)·`app-dashboard-mobile.jpg`(demo-ngn)이 어느 빌드/어느 계정 데이터인지 코드·문서에 명문화된 곳 없음(화면 내 표기로만 추정). 재캡처·교체 시 확인 필요.
2. **광고 대시보드 날짜 불일치 교체 가능 여부** — 3월 11일 vs 7월 12일 불일치를 고치려면 실제 앱을 재캡처해야 하는데, 그 앱 접근·데모 데이터 세팅 가능 여부 미확인.
3. **S5 모바일 버튼 배열** — 코드상 모바일 세로 스택(§7-7)은 확인했으나, 실기기/모바일 뷰포트에서 secondary 버튼 폭·줄바꿈이 의도대로인지 렌더 검증 미실시(이번엔 구현 안 하므로 미검증).
4. **철학 섹션 이동 시 애니메이션·레이아웃 의존성** — `MOCKS` 인덱스 매핑(§7-5)·FadeUp delay 스태거가 막 재배치 시 어떻게 깨지는지는 실제 이동 후 렌더로만 확정 가능(현재 미검증).
5. **home.ts 폐기 export의 실제 참조처** — `branch`·`features` 등이 홈 외 다른 라우트(`/content`·`/ads` 등)에서 쓰이는지 전수 확인 필요(정리 전 grep 요).

> 위 항목은 전부 **이번 작업에서 미검증**. 이번은 문서화만 했고, 실기기 렌더·앱 재캡처·전수 grep은 각 Phase에서 수행 예정.
