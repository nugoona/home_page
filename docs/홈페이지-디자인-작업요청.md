**요구(§3.3)** 두 제품 공통 흐름 4단계로 재구성:

1. **자료를 알려주세요** — 콘텐츠는 사진·영상, 광고는 상품·판매 자료
2. **앱이 먼저 준비합니다** — 글·이미지·광고 및 지원하는 운영 계획
3. **운영자가 결정합니다** — 확인하고 고치거나, 허용된 종류에 한해 정해둔 기준으로 자동 진행
4. **결과와 기록이 남습니다** — 발행 콘텐츠와 광고 운영 자료가 쌓인다

**⛔ 주의(§3.3 원문)** "공통 설명이 광고 예산 자동 변경이나 모든 영상의 자동 승인을 약속해서는
안 된다. 자동화 범위는 제품별로 구분한다. 초기 계정 연결은 사람이 함께 돕는 지원이다."
→ 3번의 "자동 진행"은 **허용된 종류에 한해**라는 단서를 반드시 화면에 남길 것.
영상은 자동 승인 대상이 아니다.

### ② §3.4 — 메인에 콘텐츠 운영 순환 추가 (신설)

**어디** 메인, §3.3 아래 또는 콘텐츠 제품 블록 근처
**지금** 없다.
**요구(§3.4)** 순환 한 바퀴를 **한 번만** 보여준다:

> 무엇을 만들지 정하기 → 사진·영상 올리기 또는 맡기기 → 채널별 콘텐츠 만들기
> → 검토·예약·발행 → 검색 위치 확인 → 다음 콘텐츠에 반영

**핵심(§3.4 원문)** "마지막 두 단계가 단순 글 작성 도구와의 차이다."
→ **'검색 위치 확인 → 다음 콘텐츠에 반영'이 이 그림의 주인공**이다. 앞 단계를 크게 그리고
마지막 두 개를 작게 그리면 의미가 없다.
**⛔** "순위 상승을 보장하는 그림은 만들지 않는다"(§3.4).

## 5. 클로드가 작업하며 발견한 것 — 코덱스가 알면 시간 아낄 것

1. **카피가 화면 컴포넌트에 하드코딩된 데가 많다.** 오늘만 5곳에서 발견했다
   (매출·광고 문장 / 시장 조사 / 자산 결론 / 3단계 라벨 / 마무리 문장).
   `lib/content/*.ts`만 고치면 화면이 안 바뀌는 경우가 있으니, **고친 뒤 렌더된 HTML에서
   실제로 나가는지 확인**할 것: `curl -s http://localhost:3131/ | grep -F "문구"`
2. **같은 문구가 PC용·모바일용 파일에 각각 들어 있다.** 한쪽만 고치면 다른 쪽이 남는다.
3. **화면에 안 쓰이는 죽은 데이터가 있다.** `market.items[0]`, `catalog.panel`,
   `RPT_TOC`(void 처리) 등. 고쳐도 화면이 안 바뀌니 먼저 사용처를 grep할 것.
4. **`globals.css`의 `a { color: inherit }`가 Tailwind 유틸보다 우선한다.**
   `<a>` 태그에 `text-white`를 걸어도 안 먹는 경우가 있다(요금 추천 버튼이 그랬다).
   다크 배경 버튼을 만들 때는 **인라인 style로 색을 못박고, 만든 뒤 명암 대비를 실제로 재라.**
5. **`OccupancyGrid`는 셀이 정사각형**(`aspectRatio: cols/rows`)이다. 내용이 줄면 `rows`도
   줄여야 여백이 안 남는다(§8.16 "카피가 바뀌면 행 수 재실측").
