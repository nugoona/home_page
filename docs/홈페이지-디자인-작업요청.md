## 0. 최신 지시 — 현재 시안 불채택, 기존 디자인으로 돌아가 필요한 내용만 반영 (2026-09-18 재지적)

### 이번 재지적이 이전 보완 지시보다 우선한다

사장님은 클로드 수정본(`0fe5b69`)의 모바일 화면 3장을 보고 다음과 같이 재지적했다.
> “텍스트가 좋다고 해서 읽히는 게 아니야.”
> “홈페이지라는 거는 이렇게 텍스트가 많아버리고 그다음에 정보 전달이 제대로 하나도 안 돼.”
> “내가 분명히 텍스트 꾸역꾸역은 지적을 했는데.”

**현재 `/content2` 디자인은 채택하지 않는다.** 코덱스 최초 시안(`67b8a20`)으로 되돌리는 것도 답이 아니다. 두 시안 모두 설명을 과하게 쌓는 같은 문제가 있다. 기존 `/content`의 공들인 디자인을 출발점으로 삼고, 승인된 기획 중 부족한 내용만 기존 장면에 반영한다. 현재 시안에 사진·아이콘·선·움직임을 더 붙이는 보완 방식은 중단한다.

**유지할 것은 전달할 의미이지 문장 전부가 아니다.** 이전의 ‘승인된 문구 유지’를 모든 문장을 화면에 남기라는 뜻으로 해석하지 않는다. 제목·본문·라벨이 반복하는 말은 덜어내고, 그림으로 전달되는 설명은 다시 글로 반복하지 않는다. 기능·가격·지원 조건의 사실은 유지하되 표현은 짧게 재편할 수 있다. 필요한 조건은 관련 행동 가까이에 읽히게 두며, 모든 구간 아래에 방어적인 주석을 반복하지 않는다.

첨부 화면에서 확인한 실패와 수정 기준:
- **첫 화면:** 긴 제목과 설명이 화면을 차지하고 핵심 장면이 아래로 밀렸다. 기존 첫 화면의 구도와 밀도를 기준으로 제목을 짧게 정리하고, 서비스를 이해할 장면이 먼저 보이게 한다.
- **글감 구간:** 제목·보조 설명·‘시작은’·‘가게 이름’·‘하나면 됩니다’가 같은 의미를 반복한다. 반복 문장을 없애고 검색어·글감·촬영 안내의 연결을 기존 시각 모듈 안에서 보여준다.
- **검색 구간:** 표·설명 상자·주석이 누적돼 핵심이 묻힌다. 기존 검색 현황 장면을 살리고 ‘확인 결과가 다음 콘텐츠에 반영된다’는 관계만 명확히 보완한다.
- **공통:** 줄바꿈·글자 크기·여백 조정만으로 끝내지 않는다. 작은 글씨로 욱여넣거나 긴 문장을 화면 밖으로 보내지 말고 화면에 남길 정보 자체를 줄인다. 한 화면을 보자마자 핵심 하나가 읽히는지 실제 모바일 캡처로 판정한다.

**원복의 범위:** 원본 `/content`는 시안 작업으로 변경되지 않았으므로 원본 코드를 되돌릴 필요가 없다. 승인된 요금·기능 오류 교정·데모/로그인 동선 수정도 유지한다. 현재 시안은 Git 이력으로 보존하고, 기존 `/content`를 기준으로 `/content2`에서 필요한 변경만 비교할 수 있게 준비한다. 원본 적용·배포는 하지 않는다. 이번 코덱스 요청은 이 지시를 문서에 남기는 것이며 실제 코드 원복은 수행하지 않았다.

### 사장님 판단과 승인 범위

사장님 원문:
> “기획은 좋고 뭘 보여줘야 할지는 확실히 맞아. 이 방향이 맞아.”
> “모바일은 조금 텍스처가 꾸역꾸역 너무 많이 들어와서 안 보여. 뭔 말하려고 하는지 잘 안 보이고.”

**기획과 보여줄 내용은 승인됐다. 디자인은 승인되지 않았다.** 코덱스가 만든 `/content2`는 구성과 설명 흐름을 확인한 시안이다. 타입 검사·버튼 동작·가로 넘침 검사는 통과했지만, 그것이 디자인 완성도나 모바일 전달력의 합격을 뜻하지 않는다. “안 잘리니 완성”으로 판단하지 않는다.

이번 전달의 우선 작업은 **기존 콘텐츠 페이지의 PC·모바일 디자인을 기준으로, 아래 핵심 의미 중 부족한 부분만 반영한 비교 시안**이다. 현재 3구간 레이아웃이나 전체 8구간 재편을 강제하지 않는다. 아래 7개 전체를 한꺼번에 새로 구현하라는 뜻도 아니다.

### 유지할 기획

1. 지금 올리기와 사진 맡기기의 차이를 보여준다.
2. 가게 이름에서 목표 검색어·추천 글감·촬영 안내로 이어지는 관계를 보여준다.
3. 검색 위치 확인이 다음 콘텐츠 준비로 이어짐을 보여준다.

실제 앱 지원 범위, 승인된 상품 정책과 기존 캐러셀 유지 결정은 바꾸지 않는다. 문구는 의미와 사실을 보존하면서 축약·통합할 수 있다. 핵심 기획을 모두 별도 구간·문장으로 전시하지 않고 기존 장면에 흡수한다. 기능·조건을 왜곡하거나 새 약속을 만들지 않는다.

### 디자인에서 해결할 문제

- **모바일:** 글·라벨·선·상자·아이콘이 한꺼번에 경쟁해 무엇을 말하는지 잘 안 보인다. 단순히 글자를 더 작게 하거나 PC 구도를 세로로 쌓지 않는다. 한 장면에서 주 메시지 하나가 먼저 보이고, 그림이 그 메시지를 설명하며, 보조 설명은 그다음에 읽히도록 재설계한다.
- **PC:** 비슷한 상자와 설명이 반복되고, 아이콘·텍스트가 자료 변환 장면을 대신하고 있다. 기존 홈페이지의 구도·여백·시각적 밀도를 기준으로 구간마다 필요한 크기와 배치를 다르게 잡는다. 큰 빈칸을 두거나 장식을 더하는 것으로 해결하지 않는다.
- **자료 준비:** 사진을 직접 올리는 경우와 한꺼번에 맡기는 경우의 결과 차이를 구체적으로 보여준다. 현재 폴더 아이콘과 문장만 있는 표현은 최종안으로 보지 않는다.
- **글감 준비:** 가게 이름은 실제로 입력할 수 있는 검색창처럼 보이지 않게 한다. 검색어·글감·촬영 안내의 관계가 설명을 전부 읽기 전에도 이해되어야 한다.
- **발행 이후:** 검색 확인에서 다음 콘텐츠로 이어지는 관계가 주인공이다. 순위 상승·성과 보장 그림으로 바꾸지 않는다.

### 작업 방식과 지킬 경계

- 먼저 기존 홈·콘텐츠의 실제 PC·모바일 화면, DESIGN §8.13·15·16·17·18, 두 소스 갤러리를 확인한다. 조사 우선 리디자인 지침을 적용한다.
- 검정·흰색·파란색, 글꼴·큰 제목·가는 선 등 기존 브랜드 완성도를 유지한다. 현재 시안의 상자 배치나 크기까지 유지해야 하는 것은 아니다.
- **작업 위치:** `nugoona/app/content2/`의 별도 비교 시안. 디자인 출발점은 기존 `/content` 실물이다. `67b8a20`·`0fe5b69`는 불채택 시안 이력이며 재사용을 강제하지 않는다. 실제 작업 전 최신 변경 상태를 확인한다.
- **원본 `/content`·메인·광고·요금은 보존한다.** 시안 보완 때문에 공통 스타일·부품을 바꿔 원본에 영향을 주지 않는다. 필요한 스타일은 시안 범위에 둔다.
- 모듈 구현을 우선한다. 필요하면 실제 앱의 관련 부분을 활용하되 설명용 그림과 실제 화면을 구분한다. 이미지가 고객 이해에 꼭 필요할 때만 직접 제작하거나 필요한 장면·목적을 구체적으로 알려준다. 생성 그림으로 실제 기능이나 성과를 꾸미지 않는다.
- 움직임은 변환·순서·선택 결과를 이해시키는 데만 사용한다. 장식용 움직임을 늘려 모바일을 더 복잡하게 만들지 않는다.
- PC와 모바일 모두 실제 렌더를 보고, 선택 전환·시작 버튼까지 확인한다. 모바일은 390px뿐 아니라 320px에서도 읽힘과 누르기 편한 크기를 확인한다.
- **사용자에게 실제 캡처와 로컬 확인 링크로 보여준다.** 코드나 설명만으로 완료 보고하지 않는다. 시안 확인 후 피드백을 받으며, 원본 적용·배포는 별도 지시 전까지 하지 않는다.

### 클로드에게 기대하는 결과

**기존 디자인을 살리고, 문장을 덜어내고, 필요한 장면만 바꾼 PC·모바일 비교 시안**을 보여준다. 현재 시안의 상자와 텍스트를 조금 다듬은 결과를 다시 제출하지 않는다. 기존 화면과 나란히 비교할 캡처와 링크를 제공하고, 무엇을 덜어냈고 어떤 핵심이 더 잘 보이는지 짧게 보고한다.

2. **앱이 먼저 준비합니다** — 글·이미지·광고 및 지원하는 운영 계획
3. **운영자가 결정합니다** — 확인하고 고치거나, 허용된 종류에 한해 정해둔 기준으로 자동 진행
4. **결과와 기록이 남습니다** — 발행 콘텐츠와 광고 운영 자료가 쌓인다

**⛔ 주의(§3.3 원문)** "공통 설명이 광고 예산 자동 변경이나 모든 영상의 자동 승인을 약속해서는
안 된다. 자동화 범위는 제품별로 구분한다. 초기 계정 연결은 사람이 함께 돕는 지원이다."
→ 3번의 "자동 진행"은 **허용된 종류에 한해**라는 단서를 반드시 화면에 남길 것.
영상은 자동 승인 대상이 아니다.

### ② §3.4 — 메인에 콘텐츠 운영 순환 추가 (신설)

**어디** 메인, §3.3 아래 또는 콘텐츠 제품 블록 근처
**지금** 없다.

마지막 두 개를 작게 그리면 의미가 없다.
**⛔** "순위 상승을 보장하는 그림은 만들지 않는다"(§3.4).

## 5. 클로드가 작업하며 발견한 것 — 코덱스가 알면 시간 아낄 것

1. **카피가 화면 컴포넌트에 하드코딩된 데가 많다.** 오늘만 5곳에서 발견했다
   (매출·광고 문장 / 시장 조사 / 자산 결론 / 3단계 라벨 / 마무리 문장).
   `lib/content/*.ts`만 고치면 화면이 안 바뀌는 경우가 있으니, **고친 뒤 렌더된 HTML에서
   실제로 나가는지 확인**할 것: `curl -s http://localhost:3131/ | grep -F "문구"`
2. **같은 문구가 PC용·모바일용 파일에 각각 들어 있다.** 한쪽만 고치면 다른 쪽이 남는다.
3. **화면에 안 쓰이는 죽은 데이터가 있다.** `market.items[0]`, `catalog.panel`,
   `RPT_TOC`(void 처리) 등. 고쳐도 화면이 안 바뀌니 먼저 사용처를 grep할 것.
4. **`globals.css`의 `a { color: inherit }`가 Tailwind 유틸보다 우선한다.**
   `<a>` 태그에 `text-white`를 걸어도 안 먹는 경우가 있다(요금 추천 버튼이 그랬다).
   다크 배경 버튼을 만들 때는 **인라인 style로 색을 못박고, 만든 뒤 명암 대비를 실제로 재라.**
5. **`OccupancyGrid`는 셀이 정사각형**(`aspectRatio: cols/rows`)이다. 내용이 줄면 `rows`도
   줄여야 여백이 안 남는다(§8.16 "카피가 바뀌면 행 수 재실측").
