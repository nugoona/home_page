### 0.2 이번 실패에서 반드시 바꿀 것

사용자 지적: **“텍스트가 좋다고 해서 읽히는 게 아니야.”**, **“내가 분명히 텍스트 꾸역꾸역은 지적을 했는데.”**

- 기술 검사·버튼 동작·가로 넘침 없음은 기본 조건일 뿐이다. 사용자에게 메시지가 읽히고 기존보다 보기 좋아졌는지가 디자인 합격 조건이다.

### 0.5 원본을 보호하는 구현 방식

- 콘텐츠는 `/content2`를 활용한다. 메인·광고는 기존 비교 경로가 있는지 확인하고, 없으면 `/home2`·`/ads2` 등 명확히 분리된 경로를 만든다. 기존 `/ads2`에 사용자 선택 시안이 있으면 덮어쓰지 말고 먼저 확인해 보존한다.
- `/`·`/content`·`/ads`·`/pricing`와 공통 스타일의 기존 출력은 그대로 유지한다. 완료된 문구·요금·기능 오류 교정·동선 수정도 유지한다.
- **공용 부품이라는 이유로 작업을 멈추지 않는다.** 기본값을 그대로 둔 선택 인자나 시안 전용 조립으로 필요한 부분만 바꿀 수 있다. 공용 부품을 수정했다면 원본 출력이 그대로인지 회귀 확인한다. 한 문장 때문에 수백 줄 전체 복제를 먼저 선택하지 않는다.
- 푸터·메뉴도 원본에 영향을 주지 않는 비교 방법을 사용한다. 주소만 비교 시안이라고 해놓고 공유 CSS나 공용 부품 때문에 원본이 변하면 실패다.
- 기존 미커밋·미추적 사용자 작업을 보존하고 담당 파일만 커밋한다. 클로드 기록은 클로드 공책에, 기존 정본에는 최신 결정과 상태를 갱신한다.
- 현재 시안과 과거 안은 Git 이력으로 보존한다. 작업 편의를 위한 저장소 전체 원복·강제 덮어쓰기·사용자 자료 삭제는 하지 않는다.

### 0.6 디자인과 이미지 기준

**기본 선택 순서: 기존 모듈 활용 → 기존 모듈 확장 → 맞는 소스 모듈 재조립 → 필요한 새 모듈·이미지.** 추가 자체를 금지하지도, 장식을 늘리는 것을 개선으로 보지도 않는다.

- 기존 색·폰트·로고·가는 선·구획·여백·밝고 어두운 리듬에 맞춘다. 같은 폰트와 색만 썼다고 같은 디자인이 되는 것은 아니다. 제목과 장면의 비율, 화면의 밀도와 시선 흐름까지 맞춘다.
- 모바일은 PC를 좁게 쌓은 버전으로 끝내지 않는다. 제목, 핵심 그림, 짧은 보조 설명의 순서를 잡고, 읽는 양과 누르는 위치를 실제 휴대폰 폭에서 확인한다.
- 그림으로 설명할 수 있는 일을 라벨·본문·캡션에서 반복하지 않는다. 의미가 필요한 문구를 무조건 잘라내거나 작은 회색 글씨로 밀어내지도 않는다.
- 새 이미지가 필요한 경우 구간의 목적을 정하고 직접 제작·검수한다. 코덱스 제작이 필요한 경우에는 대상 구간·이미지가 설명할 내용·비율·기존 디자인과의 관계를 구체적으로 전달한다. 막연히 ‘이미지가 필요하다’고 사용자에게 제작을 맡기지 않는다.
- 실제 앱 증거는 실제 화면·자료를 사용한다. 설명 모듈·예시 수치는 구분하고 생성 이미지로 실제 기능·성과를 꾸미지 않는다. 앱 전체를 작게 축소해 읽히지 않는 화면을 넣지 않는다.
- 꼭 필요한 변환·선택·관계만 움직이게 한다. 텍스트 과밀 위에 애니메이션까지 얹지 않는다.

### 0.7 순서·검수·완료 조건

1. 최신 Git·지도·정본·실물과 기존 재사용 자산 확인.

## 5. 클로드가 작업하며 발견한 것 — 코덱스가 알면 시간 아낄 것

1. **카피가 화면 컴포넌트에 하드코딩된 데가 많다.** 오늘만 5곳에서 발견했다
   (매출·광고 문장 / 시장 조사 / 자산 결론 / 3단계 라벨 / 마무리 문장).
   `lib/content/*.ts`만 고치면 화면이 안 바뀌는 경우가 있으니, **고친 뒤 렌더된 HTML에서
   실제로 나가는지 확인**할 것: `curl -s http://localhost:3131/ | grep -F "문구"`
2. **같은 문구가 PC용·모바일용 파일에 각각 들어 있다.** 한쪽만 고치면 다른 쪽이 남는다.
3. **화면에 안 쓰이는 죽은 데이터가 있다.** `market.items[0]`, `catalog.panel`,
   `RPT_TOC`(void 처리) 등. 고쳐도 화면이 안 바뀌니 먼저 사용처를 grep할 것.
4. **`globals.css`의 `a { color: inherit }`가 Tailwind 유틸보다 우선한다.**
   `<a>` 태그에 `text-white`를 걸어도 안 먹는 경우가 있다(요금 추천 버튼이 그랬다).
   다크 배경 버튼을 만들 때는 **인라인 style로 색을 못박고, 만든 뒤 명암 대비를 실제로 재라.**
5. **`OccupancyGrid`는 셀이 정사각형**(`aspectRatio: cols/rows`)이다. 내용이 줄면 `rows`도
   줄여야 여백이 안 남는다(§8.16 "카피가 바뀌면 행 수 재실측").
