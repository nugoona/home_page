# SRS 13 — 노출 소식 엔진

> 사장님이 특히 중요하게 꼽은 기능. 마스터 = [SRS.md](../SRS.md). 공통 불변식(§2)을 상속한다.
> 근거: `docs/EXPOSURE.md` §6(파이프라인 단일 진실), 메모리 `feedback_exposure_news_judge_framework`,
> 코드 `worker/src/exposure/collect-news.ts`·`judge-news.ts`·`apply-news-judgment.ts`·`content/policy-refresh.ts`.
> ⚠️ 노출소식 수집·판정·directive 주입·미발행 재생성 코드를 건드리기 전 EXPOSURE.md를 먼저 읽는다.

## 1. 목적
네이버·인스타·구글·당근의 **노출(검색에 잘 보이기) 관련 업데이트·규칙 변화를 우리가 대신 주 1회 챙겨**,
정직하고 우리에게 도움 되는 것은 앞으로 쓰는 글에 자동으로 녹이고, 거짓·기만은 버린다. 사장님이 네이버
공식 블로그나 SEO 커뮤니티를 매일 들여다보지 않아도, 우리 글쓰기가 **최신 노출 환경에 맞게 스스로 따라가게**
하는 기능. 검색 노출이 이 앱의 목적이므로, 규칙이 바뀌면 우리 글도 바뀌어야 뒤처지지 않는다.

## 2. 액터·트리거
- **액터**: 워커(수집·판정 크론), Claude(웹서치 수집 + 소식 판정), 운영자(누구나컴퍼니, 애매한 건만 승인), 사장님(피드 확인).
- **트리거**:
  - **수집 크론**: 주 1회 일요일 23:00 `collect-exposure-news` — 매체별로 Claude 웹서치 호출.
  - **판정 연쇄**: 수집 직후 같은 크론에서 미판정 소식을 Claude가 판정(`judgeAndApplyUnjudgedNews`).
  - **정책 갱신 재생성**: 노출 규칙이 바뀌어 정책버전이 오르면 `policy-refresh` 크론이 예약된 옛 글을 재생성.
  - **승인(EXP-10)**: needs-human으로 보류된 지침을 운영자가 `/admin/exposure`에서 승인·반려.

## 3. 입력
- **매체 5종 조사 범위**: 네이버 플레이스·네이버 블로그 검색·인스타그램·당근 비즈프로필·구글 비즈니스 프로필.
  각 매체마다 "무엇을 조사하라"는 scope(공식 발표 우선, 커뮤니티 추정은 trust 라벨)를 프롬프트로 준다.
- **기존 소식 목록**: 같은 소식 재수집 방지(프롬프트 + `exposureDedupKey` 2차 방어).
- **판정 대상 소식 카드**: medium·title·summary·ownerAction·ruleHint·trust(수집이 채운 신뢰도).
- **현재 활성 지침**: `exposureDirectives/active`(전역 단일 문서, ≤12개) — 판정 결과가 여기에 합류.

## 4. 처리 규칙·불변식

### (a) 주 1회 웹서치 수집
- 주 1회(일 23:00) 매체 묶음별로 Claude 웹서치를 호출해 **노출 관련 업데이트 뉴스·규칙**을 모아
  `exposureNews`에 `pending-review`로 적재. 비용 = Claude CLI(요금제 내) 매체당 1회 + Firestore뿐(추가 비용 0).
- 공식 발표가 드문 영역이라 커뮤니티·대행사 추정도 수집하되 **trust로 명확히 라벨**(official/press/community).
  트래픽 작업·리뷰 구매류는 "하지 말라"는 경고로만 다룬다(어뷰징 수집 금지).

### (b) Claude 판정 — 4분기, 사람 사전승인 아님
수집된 소식을 **Claude가 판정**한다("안 본 걸 미리 승인 못 한다"는 사장님 판단). `judge-news`가 4분기로 가른다:
- **adopt**(정직 + 노출 관련성↑) → `approved:true`로 지침(directive)에 **자동 반영**. 자동반영 기준 =
  우리 업체와 매칭되며 검색량 높은 키워드 × 블로그가 그 키워드에 최적화되는가(북극성=노출).
- **needs-human**(허용 가능한 기만이냐 애매한 경계) → `approved:false` + **사장님/운영자께 알림**(사람 판단 요청).
  승인 경로 = EXP-10, `/admin/exposure`에서 운영자가 승인(approve→approved:true)·반려(reject→제거).
- **notify-only** → 글에 반영 안 하고 소식으로만.
- **reject** → 버림(거짓·기만 — 방문자 위장·체험단·카더라 망상).
- **안전 폴백**: 판정 파싱·호출 실패 시 `notify-only`(자동반영 안 함). adopt/needs-human은 content-rule + 비어있지
  않은 directive일 때만 유지(잘못된 자동반영 강등). "검수 없이 전역 적용"이던 옛 위험은 승인 필터로 해소됨.
- **[상속 C-6] 무음 실패 금지.** 판정·반영 결과(무엇을·왜 바꿨는지)를 운영자에게 알린다.

### (c) ★ 미발행/발행예정 글에도 자동 반영 (핵심)
채택된 노출 규칙·지침은 **앞으로 쓸 글은 물론, 아직 발행 안 된(미발행) 예약 글에도 적용되어야 한다.** 두 경로:
1. **앞으로 생성되는 글** — 활성 지침(`buildDirectiveBlock`, `approved===true`만) + 노출 규칙(exposure-rules)이
   블로그 생성 프롬프트에 주입돼, 새 글은 자동으로 새 규칙을 반영한다.
2. **이미 예약된 미발행 글** — 노출 규칙이 정책 텍스트에 박히므로, 규칙이 바뀌면 `CONTENT_POLICY_VERSION`을 올린다
   (상속 C-4). 그러면 `policy-refresh` 크론이 예약(scheduled)된 옛 버전 글을 `writing`으로 되돌려 **현행 규칙으로
   다시 쓰고, 원 예약 시각(restoreScheduledAt)을 보존해 같은 시각으로 재예약**한다(스케줄 무손실). 옛 정책 발행 =
   소비자 기만이므로, 재생성 전에 발행 시각이 오면 발행 직전 백스톱이 보류(fail-closed).
- **[상속 C-4] 정책버전 강제.** 노출 규칙(`exposure-rules.md`)은 정책 소스 파일(POLICY_SOURCE_FILES)에 포함돼
  해시 가드가 감시한다 — 규칙을 바꾸면 버전 bump가 강제되고 미발행 글 재생성이 자동으로 도는 것이 목표 동작이다.
- 레거시 이식 글(legacyPostNumber)은 과거 발행본 재게시라 재작성 제외(금지어·사진·키워드는 발행 직전 게이트 적용).

### (d) 지침 저장·소비 규칙
- **전역 단일 문서** `exposureDirectives/active`(업체별 아님, ≤12개). 소비는 **블로그 생성 프롬프트에만**,
  `approved===true`만 주입. 정적 규칙(`exposure-rules.md`)은 Firestore가 아니라 파일 — 사람 손(운영자 승인+버전
  헤더+git)으로만 변경(검수됨). directive(자동, 애매한 건 승인 게이트) vs 정적 규칙(사람 검수)의 두 층.

## 5. 출력·성공
- **수집 결과**: `exposureNews` 소식 카드 적재 + 판정 verdict(adopt/needs-human/notify-only/reject) 기록 + 근거 한 줄.
- **자동 반영**: adopt 소식이 `exposureDirectives/active`에 `approved:true`로 합류 → 그때부터 새 블로그 글 프롬프트에 주입.
- **미발행 글 반영**: 노출 규칙 변경으로 정책버전이 오르면, 예약된 미발행 글이 원 예약 시각을 지킨 채 현행 규칙으로
  재생성된다(목표 동작). 발행본은 안 건드리고, 재생성 실패·과거 예약은 로그로 관측.
- **사장님/운영자 알림**: 판정·반영 시 무엇을 왜 바꿨는지 텔레그램 공지. needs-human은 승인 대기로 EXP-10 목록에 뜸.
- **소식 피드**: `/exposure` 화면에 소식 카드(출처 뱃지 공식/확인된 소식/업계추정, 추정은 "참고용" 경고, 규칙 반영
  상태 정직 표기). 홈에는 최신 1건 + `/exposure` 링크. 키워드 순위 카드(SRS 12)와 한 화면에서 노출을 종합해 보여준다.

## 6. 예외·경계
- **판정 실패(파싱·타임아웃)**: 안전 폴백 notify-only — 자동반영 안 함(검수 없으니 "확실할 때만 반영"이 기본값).
- **애매한 기만**: needs-human으로 보류 → 사장님 승인 전엔 프롬프트에 안 들어감(EXP-10 승인 게이트).
- **거짓·기만 소식**: reject — 글에도 소식 피드에도 노출 안 함.
- **재생성 중 삭제·발행된 글**: policy-refresh가 트랜잭션 CAS로 여전히 예약 상태일 때만 재생성·복원(부활·중복 방지).
- **한 회차 백로그 다발**: 판정 상한(JUDGE_CAP=20)·재생성 상한(REFRESH_CAP=20)으로 LLM·워커 폭주 방지, 초과분은
  다음 회차(침묵 절단 아님, 로그).
- **잘못된 지침 우려**: 전역 단일 문서라 파급이 크므로 승인 게이트(approved만 주입) + LLM 안전 강등이 완화 장치.

## 7. 수용 기준
- [ ] 주 1회 크론이 매체 5종에서 노출 소식을 수집해 `pending-review`로 적재한다.
- [ ] Claude가 정직+노출관련이면 adopt(자동반영), 거짓·기만이면 reject, 애매하면 needs-human으로 가른다.
- [ ] adopt 지침이 앞으로 생성되는 블로그 글 프롬프트에 `approved===true`만 주입된다.
- [ ] 노출 규칙이 바뀌어 정책버전이 오르면, 예약된 미발행 글이 원 예약 시각을 지킨 채 현행 규칙으로 재생성된다.
- [ ] needs-human 건은 `/admin/exposure`에서 운영자가 승인해야 반영되고, 승인 전엔 프롬프트에 안 들어간다.
- [ ] 판정 실패 시 자동반영되지 않고 notify-only로 안전하게 떨어진다.
- [ ] `/exposure` 피드에 출처 뱃지·추정 경고·규칙 반영 상태가 정직하게 뜬다.
- [ ] 검증: 수집·판정은 실 LLM 스모크로 판정 품질 눈 확인(잘못 adopt 안 하나) / 정책 재생성은 에뮬레이터 통합
      (예약 보존·CAS) / 승인 경로는 브라우저 E2E.

## 8. 현재 상태
✅ 라이브(엔진). 주 1회 수집·Claude 4분기 판정·adopt 자동반영(새 글)·needs-human 승인 경로(EXP-10 `/admin/exposure`)
동작. **미발행 글 자동 반영의 실제 상태(정직)**: 노출 규칙(exposure-rules, 사람 검수)이 바뀌면 정책버전 bump →
`policy-refresh`가 예약 미발행 글을 재생성(원 예약 보존)하는 경로는 라이브. 반면 **소식 판정으로 새로 생긴
directive에 의한 미발행 글 선별 재생성(EXP-AUTO-02)은 현재 보류**(사장님 2026-06-24 지시 "지침에 실제 어긋나는
글만 고치는 선별 재작성을 설계·구현한 뒤 켠다") — 그때까지 directive는 새로 쓰는 글에만 반영된다.
⚠️ ③실 LLM 판정 품질은 CLI 환경 제약으로 일부 미검증(JSON 메커니즘은 기존과 동일). 상세 = `docs/STATUS.md`.
감사 = `docs/BUG-REGISTER.md`(exposure-1·EXP-AUTO-*).
