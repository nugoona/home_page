## 1. 목적
사장님이 **영상 소재만 올리면**, 시스템이 알아서 편집자에게 넘길 수 있는 형태로 다듬고(규격변환·편집 패키지),
편집이 끝난 영상을 **유튜브 쇼츠·인스타 릴스로 자동 게시**한다. 사장님은 영상 편집이나 업로드 도구를
몰라도 된다. 영상 준비의 번거로운 뒷일을 시스템이 대신 갖춰 두는 것이 이 기능의 존재 이유다.

세 덩어리로 나뉜다.
- **A. 자동 편집 준비**(사장님 화면엔 안 보임): 올린 소재를 규격변환 + 편집 패키지로 만들어 편집 폴더에 둔다.
- **B. 음성으로 편집 요청**: 사장님이 "이렇게 편해졌으면 좋겠다"를 **타이핑 없이 마이크(음성)만으로** 전한다.
- **C. 유튜브 쇼츠 자동 업로드**: 편집 완료 영상을 쇼츠·릴스로 게시.

## 2. 액터·트리거
- **액터**: 사장님(소재·음성 요청 올림), 앱, 워커(발행 엔진), 영상 사이드카(옆 레포 stage3 Python), 편집자(사람), 유튜브·인스타 API.
- **트리거**:
  - **소재 업로드**: 사장님이 영상 업로드 화면에서 영상 + (선택)편집 요청을 올림 → `/api/video/complete` → `videoSourceUploads(status=pending)`.
  - **소재 배달(자동)**: `video-source-watcher`가 `pending` 감지 → 로컬 `_소재` 폴더로 배달.
  - **규격변환·편집 패키지(자동)**: 사이드카(stage3)가 `_소재`를 감시 → `D:\영상편집`으로 규격변환본 + 편집 패키지 생성.
  - **편집본 처리(자동)**: 편집자가 완성한 영상을 `edited-video-watcher`가 감지 → reel·shorts 콘텐츠(검토 대기) 생성.
  - **발행(자동)**: 사람 검토·승인 후 스케줄 흐름(SRS 04)에 합류 → 유튜브·인스타 업로드.

## 3. 입력
- **영상 소재**: 폰·PC에서 올린 원본 영상(mp4 등). GCS `uploads/`에 저장 + `videoSourceUploads(status=pending)` 문서.
- **편집 요청(선택)**: 텍스트 또는 **음성**. 음성은 마이크로 받아 AI가 정리한 뒤 요청 텍스트가 된다
  (`editRequest.text` + `editRequest.source='voice'|'text'`). 빠른 업로드는 요청 없이 소재만 올려도 된다.
- **편집 프리셋(선택)**: 편집 스타일(자동·자막·AI 나레이션·본인 음성·현장음)·음악 여부 등. 요청 텍스트로 구조화되어 편집자에게 전달.
- **편집 완성본**: 편집자가 만든 최종 영상 파일(파일명에 `{eventId}`를 담아 신원 표시).
- **테넌트 프로필**: 업체명(= 편집 폴더 신원, §4)·유튜브/인스타 발행 자격.

## 4. 처리 규칙·불변식
영상 흐름은 **세 레포**(우리 앱·워커 · 옆 레포 편집 자동화 · 발행 어댑터)에 걸치고, 유일한 연결고리는
**로컬 폴더 이름**이다. 폴더명이 한 글자만 어긋나도 조용히 누락된다(VIDEO.md §0).

### A. 자동 편집 준비 (사장님 비노출, "시스템이 갖춰져 있어야 한다")
- **[VID-소재] 저장 구조는 불변** — `_소재/<업체명>/<업로드날짜>/<원본파일명>`. 이 구조 그대로가 **옆 레포 쇼츠 자동화의 입력**이라
  합치거나 이름을 바꾸면 옆 레포에서 영상이 엉뚱한 업체로 섞이거나 사라진다. 업체명 = 옆 레포 brand(VIDEO.md §6-D).
- **[VID-규격변환] 규격변환 + 편집 패키지는 사이드카가 자동 생성** — 소재가 배달되면 사이드카(stage3)가 규격변환
  (H.264 1080p, NVENC GPU 가속) + 편집 패키지(FCP7 XML 편집 지시서·SRT·자막·받아쓰기)를 만들어 `D:\영상편집\<업체명>`에 둔다.
  옆 레포(ngn-shorts-reels-automation)와 폴더로만 주고받는 **별도 상주 프로세스**다(Node 워커와 한 몸이 아님 — Python·ffmpeg·faster-whisper).
- **[VID-사이드카] 사이드카는 무인 상주 + 크래시 자동 재시작** — `start_video_sidecar.vbs`가 런처·단일 인스턴스 가드·
  지수 백오프 재시작·UTF-8 한글 경로를 책임진다. ⚠️ **한글 경로 리터럴을 VBS에 넣지 않는다**(CP949 오독으로 WinError 123 크래시 — stage3 기본값에 위임).
- **이건 사장님 화면엔 안 보인다** — 하지만 "시스템이 갖춰져 있어야 한다"로 규격한다. 사장님은 소재만 올리고, 준비 뒷일은 시스템이 대신한다.

### B. 음성으로 편집 요청 (★ 새 요구사항, 목표 기준)
- **[VID-음성] 타이핑 없이 마이크만으로 편집 요청.** 사장님이 영상을 올릴 때 "이렇게 편해졌으면 좋겠다"는 요청을
  **음성으로만** 전할 수 있어야 한다. 키보드 타이핑을 강요하지 않는다(가게 운영 중 손이 바쁜 사장님 배려).
- **[상속 C-공통 · SRS 01 음성 규칙] 음성 후 AI 정리.** 원시 받아쓰기(STT raw)·받아쓰기 화면을 사장님에게 노출하지 않는다.
  마이크로 말하면 AI가 정리한 뒤 요청으로 들어간다. 음성 인식 실패 시 조용히 삼키지 않고 폴백 안내.
- **[VID-요청전달] 요청은 편집자에게 그대로 전달** — 음성/글 요청은 소재 옆 `<파일명>.편집요청.txt`에 `[편집 요청 · 음성]` 또는
  `[편집 요청 · 글]`로 기록되어 편집자가 읽는다. 요청이 없으면 파일을 만들지 않는다(빈 요청·내부 플레이스홀더 누출 금지).

### C. 유튜브 쇼츠·릴스 발행
- **[상속 C-4] 발행 = 엔진 결정 · 하드캡 채널당 하루 1건 · 업체별 스케줄.** 영상도 글과 동일한 스케줄 정책.
- **[VID-검토] 영상도 사람이 검토한다** — 편집본은 reel·shorts **검토 대기** 콘텐츠가 되고, 승인 후에만 발행된다.
  **검열 게이트 없는 완성본 자동발행 경로는 영구 비활성**이다(VIDEO.md §4·불변식 A). env 플립으로 못 켠다.
- **[VID-멱등] 같은 편집본은 정확히 한 번** — `(eventId, 인덱스)` 기준 멱등 가드로 reel·shorts 중복 생성·중복 발행 차단(상속 C-6).
- **[VID-유튜브] 유튜브 업로드 규격** — 쇼츠로 게시. 제목·설명·태그(한국어 기본), 커스텀 썸네일은 시작 후 2초 프레임(best-effort, 실패해도 발행 성공).
  공개 범위 = **public**(쇼츠 공개 노출이 목적). 현재 발행 자격은 **환경변수 refresh token 방식**(채널별 `YT_REFRESH_TOKEN_*`).
- **[VID-릴스] 인스타 릴스 업로드** — per-tenant 자격(있으면 우선), 없으면 계정+env 폴백. 커버 = 시작 후 2초 프레임.

## 5. 출력·성공
- **A**: 소재가 `_소재/<업체명>/<날짜>/<원본명>`에 배달되고, `D:\영상편집\<업체명>`에 규격변환본(H.264 1080p) + 편집 패키지(FCP7 XML·SRT·자막)가 생긴다.
- **B**: 사장님이 마이크로 말한 편집 요청이 AI 정리를 거쳐 `<파일명>.편집요청.txt`(`[편집 요청 · 음성]`)로 편집자에게 전달된다.
- **C**: 편집 완성본이 reel·shorts 검토 대기 콘텐츠가 되고, 사람 승인 후 유튜브 쇼츠(공개)·인스타 릴스로 게시된다.
  성공 시 유튜브 videoId·쇼츠 URL(`youtube.com/shorts/…`)·릴스 permalink가 남는다.

## 6. 예외·경계
- **소재 배달 중 워커 크래시**: 좀비(`processing` 고착)를 15분 후 `pending`으로 회수. 처리 3회 실패면 `failed`(무한 재시도 방지).
- **사이드카 크래시**: VBS가 지수 백오프로 자동 재시작(정상 60초+ 가동 후면 백오프 리셋). 한글 경로 오독 크래시는 stage3 기본값 위임으로 박제.
- **편집본 파일명 오타**: `{eventId}` 한 글자만 어긋나면 조용히 누락되거나 엉뚱한 event에 붙는다 — 파싱 실패 시 skip + 운영자 확인. 워커 다운 중 떨어진 편집본은 부팅 sweep으로 회수(VIDEO.md §6-B).
- **음성 인식 실패**: 텍스트 입력으로 폴백, 원시 오류·raw STT 노출 안 함(SRS 01과 동일).
- **유튜브 자격 없음**: `YT_CLIENT_ID`/`YT_CLIENT_SECRET`/채널별 refresh token이 없으면 명확한 오류로 실패(무음 아님 — 상속 C-6).
- **커스텀 썸네일 실패**: 발행은 성공, 유튜브 자동 선택으로 폴백(비치명).
- **완성본 자동발행 부활 시도**: 검열 게이트 없이 켜면 위반. `VIDEO_AUTO_PUBLISH_ALLOWED=false` 상수 + 테스트로 박제.

## 7. 수용 기준
- [ ] 소재를 올리면 `_소재/<업체명>/<날짜>/<원본명>` 구조로 배달되고, 이 저장 구조가 옆 레포 입력과 일치한다(합치기·이름 변경 없음).
- [ ] 사이드카가 소재를 규격변환(H.264 1080p, NVENC) + 편집 패키지(FCP7 XML·SRT·자막)로 만들어 `D:\영상편집`에 둔다(②/④ 실 영상 F→D 스모크).
- [ ] 사장님이 **타이핑 없이 마이크만으로** 편집 요청을 전할 수 있고, 원시 받아쓰기가 아니라 AI 정리 결과가 요청으로 들어간다.
- [ ] 음성 편집 요청이 `<파일명>.편집요청.txt`에 `[편집 요청 · 음성]`으로 편집자에게 전달된다.
- [ ] 편집 완성본이 검토 대기 콘텐츠가 되고, 승인 후에만 유튜브 쇼츠(공개)·인스타 릴스로 게시된다(무검토 자동발행 없음).
- [ ] 같은 편집본을 두 번 감지해도 reel·shorts가 한 벌만 만들어지고 중복 발행되지 않는다.
- [ ] 검증은 ②에뮬레이터/실파일시스템 통합 필수(파일 워처·chokidar·트랜잭션은 순수 로직으로 못 잡음).

## 8. 현재 상태
🟡 **부분(코드만) — per-tenant 셀프 연결 UI 미완.**
- **A. 자동 편집 준비**: ✅ **라이브**(2026-06-28). 사이드카 stage3가 규격변환(H.264 1080p·NVENC) + 편집 패키지를
  `D:\영상편집`에 생성, 부팅 자동시작 등록. ②/④ 실 영상 F→D 스모크 성공(RTX 4070 Ti). 미검증: 실 폰영상(회전·HDR)→Premiere 육안(사장님 환경).
- **B. 음성으로 편집 요청**: 🟡 **부분**. 음성 입력(`VoiceSheet`)→AI 정리→`editRequest(source='voice')` 배관과 `.편집요청.txt`
  전달은 라이브. 단, 현재는 자유 텍스트 입력칸과 **병존**(음성 버튼이 텍스트칸을 완전히 대체하지는 않음). "타이핑 없이 마이크만으로"의 목표 기준은 UI 개선 여지 있음.
- **C. 유튜브 쇼츠 자동 업로드**: 🟡 **코드만**. 업로드 로직(`upload-youtube.ts`·`upload-reel.ts`)은 완결이나, 발행 자격이
  **환경변수 refresh token 방식**(`YT_REFRESH_TOKEN_*`)이라 사장님이 화면에서 직접 연결하는 **per-tenant 셀프 연결 UI가 미완**. 공개 범위 public.

상세·검증 단계 = `docs/STATUS.md`(영상 규격변환 사이드카 stage3). 감사 = `docs/BUG-REGISTER.md`(video-*·VID-*).
