# SRS 12 — 노출 키워드·순위 추적

> 앱의 목적(검색 노출)의 심장. 마스터 = [SRS.md](../SRS.md). 공통 불변식(§2)을 상속한다.
> 근거: `docs/EXPOSURE.md`(파이프라인 단일 진실, file:line 포함), `docs/KEYWORD-TAGSET-RULES.md`(추출 룰 단일 진실).
> ⚠️ 키워드·순위·발행 태그 합류 코드를 건드리기 전 두 문서를 먼저 읽는다.

## 1. 목적
가게 정보(업종·지역·메뉴·시설·진료과목)만으로 **우리 가게를 찾게 할 검색어를 자동으로 만들어**, 발행하는
모든 글의 제목·태그·해시태그에 꾸준히 실어 검색 노출을 넓힌다. 그리고 그 검색어로 우리 가게가 **네이버·구글에서
실제로 보이는지 매일 재어** 사장님에게 카드로 보여준다. 북극성은 **"검색하면 우리 가게가 보이냐(꾸준한 노출)"**이지
등수 끌어올리기가 아니다. 사장님은 SNS·검색 마케팅을 몰라도 되게, 키워드를 손수 고르지 않아도 되게 하는 기능.

## 2. 액터·트리거
- **액터**: 워커(발행 엔진), 앱(키워드 추천·저장), Claude(순위 판정 아님 — 순위는 크롤/브라우저).
- **트리거**:
  - **키워드 생성**: 온보딩·설정에서 가게 정보가 바뀌면 즉시 재계산(결정론). 검색량 조회는 앱 추천 API 호출 시.
  - **순위 추적 크론**: 매일 07:40(KST 추정) `track-keyword-ranks`가 전 업체 추적 키워드 순위를 잰다.
  - **발행 직전 합류**: 글 생성·발행 시 추천 키워드·태그세트가 자동으로 제목·태그·해시태그에 합류.

## 3. 입력
- **가게 정보(provenance 신호)**: 업종(industry)·네이버 분류(category)·대표 메뉴(menu, 추천 플래그·순서)·
  시설(conveniences)·진료과목/과목(representativeKeywords)·지역(region 오프라인 / serviceArea 출장)·상호.
- **매장 유형(storeType)**: 오프라인(store)·출장(visit)·온라인(online).
- **업체별 제외어(excludeKeywords)**: 사장님이 설정에서 뺀 말(scope='all'이면 키워드에도 반영).
- **검색량**: 네이버 검색광고 키워드도구(searchad) 월 검색량(핵심추천 게이트에만).
- **추적 키워드(trackKeywords)**: 사장님이 고른 것(없으면 seoKeywords 폴백).

## 4. 처리 규칙·불변식
키워드는 **두 출력으로 분리**된다 — 어떤 룰로 뽑는지는 `KEYWORD-TAGSET-RULES.md`가 단일 진실이다(여기선 규격).

- **[상속 C-3] 노출 키워드 자동 생성·강제 주입.** 지역어간(구/동/역)×업종 안전어 + 상호로 결정론 조합.
  오프라인=지역 중심, 온라인=지역 배제, 출장=serviceArea 기준. 발행 태그·인스타 해시태그·블로그 제목에 자동 합류.
- **[상속 C-3] 성인·불법 금칙어 필터(§1-14).** `출장마사지`·`출장안마` 등 성매매 오염 복합어는 전 출력 경로
  (핵심추천·자동키워드·태그세트·해시태그)에서 `isProhibitedKeyword`(전역 오염어 ∪ 업체 제외어 scope:'all')
  **단일 판정**으로 차단. 검색량이 높아도 차단(합법 업체엔 계정을 죽이는 독). 합법 일반어('마사지'·'안마')는
  전역 목록에 넣지 않는다(B2B 몰살 방지) — 필요하면 업체별 제외어로.
- **[KW-A] 출처 추적(provenance).** 키워드/태그의 모든 조각은 이 가게의 실제 신호에서 나온 것만.
  신호가 없으면 걸러지는 게 아니라 **애초에 안 태어난다**(출처 없는 '혼밥'·'강남출장' 금지).
- **[KW-B] 단일 경첩.** 업종 안전어 결정은 `effectiveAutoTerms` 한 함수 — 소비처 3곳(자동키워드·서제스천·
  태그세트)이 모두 이 함수를 거쳐, 한 곳을 고치면 꼬리 전체가 보장된다. 헤드형 분류(학원·인테리어)는 헤드가
  안전어(과목은 접두 수식어). 병·의원 분류는 검색되는 진료과로 트림(`치과의원`→`치과`).
- **[KW-C] 앱·워커 미러 동기.** 추천(앱 `keyword-engine`)과 발행 태그(워커 `keyword-builder`)가 **같은 결정론
  조합**을 쓴다. `src/lib/keyword-builder.ts` ↔ `worker/src/content/keyword-builder.ts`는 동일 미러
  (diff=자기참조 주석 1줄뿐). 한쪽만 고치면 즉시 드리프트(사장님이 본 추천 ≠ 실제 발행 태그) → 반드시 양쪽 동기.
- **[KW-D] 두 출력 분리.** 노출 키워드(핵심추천)=검색량 게이트(`VOLUME_FLOOR=30`) 통과한 소수(cap 10),
  제목·순위추적에 쓴다. 발행 태그(태그세트)=검색량 게이트 **없는** 롱테일 ≤18개(`TAG_CAP=18`), 글마다 단다.
  메뉴 조합어(공릉돼지갈비)는 검색량이 0에 가까워 핵심추천엔 못 들지만 태그로 꾸준히 밀어 노출을 넓힌다.
- **[KW-E] 지역 입도 가드.** 동/행정동/동 단위 역세권/구 어간은 허용, **구 단위 역·구 형태**는 핵심추천에서
  차단(가게와 멀거나 아무도 안 검색). 광역시(부산·대전 등)는 우리가 만든 시 대표 시드에만 쓰고, 네이버 연관이
  광역시만 보고 끌어온 남의 동·메뉴는 컷. 서울·'도'는 시 대표 제외. 면/리 주소(목적지형)는 시·군 단위만.
- **[KW-F] seoKeywords 빈 배열 덮어쓰기 금지.** 추적/추천을 비울 때 seoKeywords는 보존(EXP-01 가드) — 발행
  태그·추천 통째 손실 방지.
- **[KW-G] 순위 크론 업체별 격리.** 한 업체의 깨진 데이터·일시오류가 그날 나머지 업체 미측정으로 번지지 않게
  `forEachIsolated` + 키워드 단위 try/catch + 크론 핸들러 try/catch = 3중 안전망.
- **[KW-H] 순위 데이터 없으면 글 프롬프트 무영향.** rank-signal은 순위가 없으면 빈 문자열을 반환해 프롬프트에서
  사라진다(빈 신호가 헤더만 박혀 생성이 깨지지 않게).
- **[KW-I] 등수 집착 금지(북극성).** 구글은 정확한 등수가 아니라 **"1페이지에 보이는가"**만 판정. 알림은 특정
  등수 달성이 아니라 **하락 경고만**. 안 보이는 키워드도 글마다 밀어 넓힌다는 동작 설명 톤으로만 노출.

## 5. 출력·성공
- **추천 키워드(핵심추천)**: 검색량 게이트 통과한 소수 → 사장님이 고른 것이 `trackKeywords`·`seoKeywords`로 저장.
  상호/브랜드명은 핵심추천에 포함("우리 가게를 찾는 검색").
- **발행 태그·해시태그**: 발행 직전 4곳에서 자동 합류 — 블로그 생성 태그(`mergeSeoAndTagSet`, seoKeywords 상위
  6개 + tagSet), 블로그 발행 직전(캡 30·제외어 strip 재합류), 인스타 해시태그(`mergeCaptionHashtags`, 메타
  위험태그 차단). 세 채널 모두 같은 `profile.tagSet`·`profile.seoKeywords`를 읽는다(단일 소스).
- **순위 카드**: `keywordRanks` 컬렉션에 최신 스냅샷(덮어쓰기) + 30일 시계열. 키워드당 4소스 — 블로그탭·플레이스
  (순수 HTTP)·통합검색 노출·구글 노출(상위 2개 키워드만, 실 Chrome 1개 공유로 1페이지 노출 판정).
- **글에 노출 반영**: 블로그 생성 프롬프트에 `rank-signal`이 "잘 보이는 키워드 / 아직 안 잡힌 키워드"를 넣어,
  잡힌 키워드는 제목·첫 문단에 살리고 안 잡힌 키워드는 새 각도로 더 민다.
- **홈 노출 카드**: 키워드별 순위 칩(측정 전은 "곧 확인해요"로 정직) + 노출 소식 1건 + 셋업 진행률.
  "안 보이는 키워드도 글마다 꾸준히 밀고 있다"는 노출 노력 문구(포기처럼 안 보이게).

## 6. 예외·경계
- **키워드 신호 0(분류조차 없음)**: 빈 배열. "우리 가게를 한마디로?" 3층 UX는 별도(빈도 낮음).
- **seoKeywords가 빔**: 합류 함수가 기본값 `[]`라 에러 없이 tagSet만으로 진행(발행 차단 없음). 추천 화면만 비게 됨.
- **한 업체 순위 조회 실패**: 그 업체만 건너뛰고 나머지는 계속(KW-G). 통합검색·구글은 비치명(실패 시 생략).
- **순위 데이터 없는 신규 가게**: rank-signal 빈 문자열 → 프롬프트에 헤더조차 안 들어감. 발행이 누적되며 자연히 작동.
- **금칙어가 이미 저장된 데이터**: 신규 차단만으론 부족 — 마이그레이션 스크립트(`worker/scripts/`)로 dry-run 후 제거.
- **searchad 검색량 조회 실패**: 핵심추천이 비거나 줄 수 있음(태그세트는 게이트 없어 영향 없음).

## 7. 수용 기준
- [ ] 오프라인 가게는 지역×업종·지역×메뉴 키워드가, 출장은 serviceArea 기준, 온라인은 지역 없이 나온다.
- [ ] `출장마사지` 등 성매매 오염어가 핵심추천·자동키워드·태그·해시태그 어디에도 안 나온다(검색량 높아도 컷).
- [ ] 합법 일반어('마사지'·'기업마사지')는 차단되지 않는다(B2B 안 죽음).
- [ ] 앱 추천 키워드와 실제 발행 태그가 같은 조합에서 나온다(미러 diff=자기참조 주석뿐, 코퍼스 골든 스냅샷 회귀 0).
- [ ] 매일 순위 크론이 한 업체 실패에도 나머지 업체를 다 측정한다(업체별 격리).
- [ ] 순위 데이터가 없을 때 글 생성이 깨지지 않는다(rank-signal 빈 문자열).
- [ ] 홈 카드에 순위 칩·노출 소식·셋업 진행률이 뜨고, 측정 전은 "곧 확인해요"로 정직하다.
- [ ] 검증: 결정론 빌더는 코퍼스 골든 스냅샷 / 검색량 게이트는 실 searchad 스모크(과금 주의·남발 금지) /
      순위 크론·구글 브라우저는 실 네이버·구글 1회 스모크 + ④ 배포 시 브라우저 E2E.
