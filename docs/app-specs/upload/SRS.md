# 누구나 SNS — 핵심 기능 요구사항 규격 (SRS 마스터) 📐

> **이 문서 = "이 앱이 반드시 해야 하는 핵심 기능과 각 동작 규격"의 단일 정답지.**
> 목표(되어야 할 모습) 기준으로 쓴다 — 예정(⬜) 기능도 "이렇게 동작해야 한다"로 미리 규격한다.
> **규격 ≠ 현황.** "지금 어디까지 됐나"는 이 문서가 아니라 `docs/STATUS.md`가 답한다. 여기선 각
> 서비스 SRS 끝의 "현재 상태" 한 줄만 STATUS로 링크한다(안 섞어야 드리프트가 안 난다).
> 설계 배경 = `docs/superpowers/specs/2026-07-03-srs-structure-design.md`.

## 이 문서를 쓰는 이유
넓게·체계적으로 손대는 **기능 개선·파이프라인 최적화의 선행 기준 문서**. 지금 헌법·KEYWORD-RULES·
피드백 메모리·도메인 문서에 흩어진 "지켜야 할 동작(불변식)"을 한곳에 못 박아, 최적화 중 요구사항을
실수로 깎는 드리프트를 막고 "버그냐 사양이냐"를 판정한다. 감사(BUG-REGISTER)의 상류 짝 —
감사=구멍 찾기, SRS=옳은 모양 정의.

## 2. 전 기능 공통 불변식 (모든 SRS가 상속하는 "못 건드리는 선")

> 아래는 **서비스와 무관하게 항상 참이어야 하는 규칙**이다. 각 서비스 SRS는 이걸 다시 안 적고 상속한다.
> 하나라도 깨면 콘텐츠 품질·법적 안전·비용·신뢰가 무너진다. 최적화·리팩터 시 **여기부터 지킨다.**

### C-1. 콘텐츠 목소리·품질
- **글 시점 = 사장님 본인.** 방문객·체험단·기자 위장 금지(사기). 모든 생성 글에 적용. [[feedback_business_owner_voice]]
- **인사말 금지.** "안녕하세요 OOO입니다"로 시작하지 않는다. 첫 문장부터 현장·장소로 진입. [[feedback_no_greeting_opening]]
- **한글 이탤릭 금지**(영문만) · **em dash(—) 금지**(가운뎃점·줄바꿈으로).
- **과장·최상급·미검증 속설 단정 금지.** 업종 법규(의료광고·중개대상물 표시광고 등) 준수.

### C-2. 사진 규칙 (법, 사장님 확정)
- **유효 4장 게이트.** 비슷한 앵글 중복·식별 불가(어둡고 흐림)를 제외한 **유효 사진 4장 미만이면 발행 보류.**
  판정 2단 = dHash(≤12) + Claude 비전, 실패 시 fail-closed(보류). 블로그·인스타 동일.
- **업로드 단에서도 강제.** `/new`·`/quick`에서 사진 4장 미만이면 올리기 버튼 비활성 + 규칙 안내.
  앱 `MIN_PHOTOS` = 워커 `MIN_UNIQUE_PHOTOS` = 4(단일 출처 동기).
- 영상만 올리는(권한 업체)은 예외.

### C-3. 노출(SEO) 강제 배선 — 앱의 목적
- **노출 키워드는 자동으로 만들어 강제 주입된다.** 지역어간(구/동/역)×업종 안전어 + 상호로 생성.
  오프라인=지역 중심, 온라인=지역 배제, 출장=serviceArea 기준.
- 발행 태그·인스타 해시태그·블로그 제목에 추천 키워드가 자동 합류(캡 있음). 상세 규격 = `docs/KEYWORD-TAGSET-RULES.md`.
- **성인·불법 금칙어(§1-14).** `출장마사지`·`출장안마` 등 성매매 오염어는 전 경로(키워드·태그·해시태그)에서
  `isProhibitedKeyword`(전역 오염어 ∪ 업체별 제외어 scope:'all') 단일 판정으로 차단. 합법 일반어('마사지'·'안마')는 전역 제외(B2B 몰살 방지).

### C-4. 발행 정책 (법)
- **정책버전 강제.** 프롬프트·가이드·노출규칙이 바뀌면 `CONTENT_POLICY_VERSION`을 올리고, 예약된 옛 버전
  글은 자동 재생성된다(옛 정책 발행 = 소비자 기만). 레거시 이식 글은 재작성 제외(발행 직전 게이트만 현행 적용).
- **발행 시점 = 엔진 결정, 업체는 시각 설정 불가.** 검토 후 **즉시 발행 기본**, 밀리면(미발행 승인 2+) 빈도수로 분산.
- **하드캡 = 채널당 하루 1건**(업체 설정과 무관 고정). 버스트 차단.
- **합산 금지 = 무조건 업체별** 스케줄.

### C-5. 계정·비용 게이트
- **비활성/정지 가게 = AI 비용 0.** 비활성·정지면 생성·발행 전 게이트에서 걸러 Claude 호출·발행이 안 나간다.
- **정지면 발행 안 함**(발행 직전 한 번 더 재확인 — TOCTOU).
- **운영자/업체 분리(act-as).** 운영자(누구나컴퍼니)가 업체를 만들고 "들어가기"로 대행. 복귀 인가 = `requireOperatorByRegistry`.

### C-6. 실패·관측
- **조용히 죽지 않는다.** 생성·발행 실패는 사장님(인앱) 또는 운영자(텔레그램)에게 알린다. 무음 실패 금지.
- **중복 금지 = 원자적 선점(CAS).** 생성·발행 모두 트랜잭션 CAS로 "정확히 한 번".
- **UI 기술 용어 금지.** 워커→"발행 엔진", cron→"자동 갱신", 큐→"대기 중 발행", 토큰→"인증".

## 3. 각 SRS 파일의 고정 템플릿

모든 `docs/srs/NN-*.md`는 아래 8절을 순서대로 갖는다(빠지면 미완성):

1. **목적** — 이 기능이 왜 있나(사장님 언어).
2. **액터·트리거** — 누가/무엇이 시작하나.
3. **입력** — 받는 것.
4. **처리 규칙·불변식** — 반드시 지켜야 할 규칙(마스터 §2 상속 + 이 기능 고유).
5. **출력·성공** — 정상 결과.
6. **예외·경계** — 에러·비었을 때·차단됐을 때 어떻게.
7. **수용 기준** — "이러면 완성" 체크 항목(검증 가능하게).
8. **현재 상태** — STATUS 링크 + ✅/🟡/⬜ 한 줄(규격 본문과 분리).

## 4. 문서 지도 (SRS의 근거 소스)

SRS는 아래 도메인 문서 + 실제 코드(file:line)를 근거로 쓴다(지어내지 않음):

| 영역 | 근거 문서 |
|---|---|
| 생성 | `docs/GENERATION.md`, `docs/PIPELINE.md` |
| 스케줄·발행 | `docs/SCHEDULE.md` |
| 채널 연결·발행인증 | `docs/CHANNELS.md` |
| 온보딩·크롤 | `docs/ONBOARDING.md` |
| 계정·인증 | `docs/ACCOUNT-AUTH.md` |
| 썸네일 | `docs/THUMBNAIL.md` |
| 노출 | `docs/EXPOSURE.md`, `docs/KEYWORD-TAGSET-RULES.md` |
| 영상 | `docs/VIDEO.md` |
| 복구·크론 | `docs/RECOVERY.md` |
| 콘텐츠 로테이션(글감) | `docs/CONTENT-ROTATION-CONSTITUTION.md` |
| 연쇄위험 | `docs/BLUEPRINT.md` |
| 버그·갭 | `docs/BUG-REGISTER.md` |

> **유지 규율**: 기능 규격이 바뀌면 해당 SRS 파일을 **즉시 갱신**(STATUS·BLUEPRINT처럼 드리프트 없이).
> 규격 = 목표라 자주 안 바뀐다 — 자주 바뀌면 그건 현황이니 STATUS로 보낸다.
