# 누구나컴퍼니 홈페이지 통합 개선안

작성일: 2026-09-18 · 대상: `nugoona/` · 용도: Claude 또는 Codex에 전달하는 통합 작업 기준

## 1. 이 문서의 지위와 작업 범위

사용자가 전달한 콘텐츠 개선안, 광고 개선안, 콘텐츠 요금 제안, 광고 요금 최종 결정을 통합했다. 중복된 설명만 줄이고 메시지·추천 문구·기능·요금·디자인 의도는 보존했다. 이번 요청은 문서 작성이며 홈페이지 구현·이미지 제작·배포를 시작하라는 지시가 아니다. 구현 담당자는 아직 정해지지 않았다.

- **확정:** 기존 디자인에 들인 작업을 존중한다. 내용에 필요한 재배치·추가·교체는 가능하다. 모듈 구현을 우선하며, 고객 이해에 이미지가 필요하면 작업자가 직접 제작한다. 광고 요금과 지원 범위는 §6의 최종 결정이 우선한다.
- **개선 방향 및 문구 후보:** §3~5의 페이지 구성과 문구. 구현의 기획 기준으로 사용하되 실제 지원 범위와 대조한다. 문구 하나하나가 최종 승인된 것으로 해석하지 않는다.
- **아직 제안:** 콘텐츠 플러스·스튜디오, 제공량·무료 체험 제한·묶음 가격·기존 고객 권한 유지 방식. §7을 검토 후 확정한다. 문서 작성 요청을 신규 상품 판매 승인으로 해석하지 않는다.
- **검증 상태:** 9월 17일 홈페이지 현황 조사는 로컬 코드 기준이었다. 사용자가 제공한 개선안의 앱 대조 결과·경쟁사 가격·외부 사례는 이번 문서 작업에서 재검증하지 않았다. 홈페이지 화면·클릭·실제 앱 지원 범위 검증도 이번에 수행하지 않았다.

작업 대상은 현재 로컬 `nugoona/`이며 구 외부 홈페이지나 `aurum/`가 아니다. 메인 `/`, 콘텐츠 `/content`, 광고 `/ads`, 요금 `/pricing`이 중심이다. 시작 `/start`, 공통 메뉴·로그인·문의 연결은 필요한 범위에서 함께 정리한다. 가격표는 `/pricing`에 모으고 제품 상세에 중복 신설하지 않는다. 배포는 별도 지시가 있어야 한다.

## 2. 전체 방향과 현재 문제

회사 중심 문장은 **“누구나 마케팅하는 시대”**를 유지한다. 두 제품은 복잡한 준비를 앱이 돕고 고객이 이해하고 결정한다는 같은 철학으로 설명한다.

**누구나 콘텐츠:** 사진을 블로그 글로 바꾸는 서비스라는 좁은 설명에서, 자료 준비 → 제작 계획 → 채널별 콘텐츠 → 검토·예약·발행 → 검색 위치 확인 → 다음 콘텐츠 반영이라는 운영 과정으로 넓힌다. 지금 찍은 자료뿐 아니라 기존 사진 맡기기, 글감·촬영 안내, 일정·자료·발행 기록을 보여준다. 제공 채널과 영상 범위는 계정·플랜·실제 지원 조건을 구분한다.

**누구나 광고:** 기능이 많다는 설명보다 “내 쇼핑몰 광고를 내가 이해하면서 운영할 수 있다”는 확신을 준다. 광고 제작·매출과 광고 성과 확인·궁금한 점 질문이 중심이고, 자동 상품 목록·보고서가 반복 업무를 줄이며 시장 자료가 참고를 돕는다. 앱과 사용 지원을 제공하는 상품이며 사람이 광고를 대신 운영하는 상품이 아니다.

9월 17일 조사에서 메인은 7개 큰 묶음(회사·제품 설명을 풀면 9구간), 광고는 12구간, 콘텐츠는 10구간, 요금은 4구간이었다. 옛 문서의 11구간·상세 페이지 가격 내장 계획은 현행이나 이번 개선안의 기준이 아니다. 실제 화면에 연결되지 않은 문구 데이터도 있어 구현 시 실제 연결을 확인한다.

## 3. 메인 페이지 개선안

### 3.1 첫 화면

제목 유지:
> 누구나 마케팅하는 시대

설명 후보:
> 가게의 콘텐츠도, 쇼핑몰의 광고도
> 복잡한 준비는 앱이 하고, 운영자는 확인하고 결정합니다.

기존 “이제는 이해하면서 직접 운영할 수 있습니다”의 철학을 유지하면서 운영 대상을 구체화한다. 계정 연결까지 앱이 자동으로 끝낸다는 인상은 주지 않는다. 무료 시작은 실제 `/start`로 연결한다.

### 3.2 두 상품을 결과 중심으로 소개

**누구나 콘텐츠**
> 찍어둔 사진과 영상이
> 꾸준히 발행되는 가게 콘텐츠가 됩니다.

> 블로그·인스타그램과 짧은 영상을 준비하고,
> 발행 일정과 검색 노출까지 한곳에서 확인합니다.

장면 후보: 블로그·인스타 / 쇼츠·릴스 선택, 갖고 있던 사진 맡기기, 노출 현황. 실제 제공 범위와 요금 조건을 맞춰 사용한다. 휴대폰 여러 대를 작게 나열하지 않고 한 장면을 크게 보여주며 설명을 전환한다. 상세 보기 → `/content`.

**누구나 광고**
> 광고를 만들고 운영하며
> 매출과 성과를 한 화면에서 이해합니다.

콘텐츠와 같은 설명 형식을 사용하되 광고 제작·통합 성과·질문 장면을 보여준다. 상세 보기 → `/ads`.

### 3.3 두 앱의 공통 운영 방식

광고 준비와 AI 대화에 치우친 기존 구간을 다음 흐름으로 재구성한다.

1. **자료를 알려주세요.** 콘텐츠는 사진·영상, 광고는 상품·판매 자료를 받는다.
2. **앱이 먼저 준비합니다.** 글·이미지·광고 및 지원하는 운영 계획을 준비한다.
3. **운영자가 결정합니다.** 확인하고 고치거나, 허용된 종류에 한해 정해둔 기준으로 자동 진행한다.
4. **결과와 기록이 남습니다.** 발행 콘텐츠와 광고 운영 자료가 쌓인다.

공통 설명이 광고 예산 자동 변경이나 모든 영상의 자동 승인을 약속해서는 안 된다. 자동화 범위는 제품별로 구분한다. 초기 계정 연결은 사람이 함께 돕는 지원이다.

### 3.4 콘텐츠 운영 순환

메인에서는 기능 전체를 길게 반복하지 않고 다음 순환을 한 번 보여준다.

**무엇을 만들지 정하기 → 사진·영상 올리기 또는 맡기기 → 채널별 콘텐츠 만들기 → 검토·예약·발행 → 검색 위치 확인 → 다음 콘텐츠에 반영**

마지막 두 단계가 단순 글 작성 도구와의 차이다. 실제 앱이 어떤 검색 결과를 어떤 방식으로 다음 콘텐츠에 쓰는지 확인한 뒤 표현한다. 순위 상승을 보장하는 그림은 만들지 않는다.

### 3.5 고객에게 남는 자산

기존 자산 구간은 유지하고 구체화한다.
> 발행한 글과 콘텐츠는 고객님의 계정에 남습니다.
> 검색 기록과 운영 이력은 다음 콘텐츠를 정하는 기준이 됩니다.

광고도 고객 광고 계정과 운영 기록이 다음 판단에 도움이 된다는 같은 형식으로 맞춘다. 서비스 종료 후 앱 안 기록을 무기한 조회할 수 있다는 약속과 고객 외부 계정에 발행물이 남는다는 약속을 혼동하지 않는다. 보관·조회 범위는 실제 정책과 대조한다.

### 3.6 업데이트 연표와 마감

실제 출시 이력이 아닌 2026.01·2026.04 등의 날짜를 제거한다.
> 운영하면서 필요한 기능은 계속 더해집니다.

날짜 없이 확인된 개선 방향만 제시한다: 더 정확한 목표 검색어, 더 쉬운 콘텐츠 준비, 더 분명한 발행 일정, 더 이해하기 쉬운 성과 확인.

“새로운 기능에도 기존 고객은 추가 비용이 없습니다”라는 포괄적인 약속은 플랜 정책과의 충돌을 점검한다. 광고는 §6의 확정 기준, 콘텐츠는 §7.6의 정책 확정 결과에 맞춰 정리한다. 마지막 무료 시작·요금 안내 동선은 유지하되 영상까지 전부 한 달 무료인 것처럼 공통 문구를 쓰지 않는다.

## 4. 누구나 콘텐츠 상세 — 운영 과정 중심 8구간

### 4.1 첫 화면

제목 후보:
> 찍어둔 사진과 영상이
> 꾸준히 발행되는 가게 콘텐츠가 됩니다

설명 후보:
> 무엇을 올릴지 정하고, 채널에 맞게 만들고, 예약 발행합니다.
> 발행 후에는 실제 검색 위치를 확인해 다음 콘텐츠에 반영합니다.

기존 “검색 결과에 내 가게가 보이길 원합니다”의 고객 열망은 살릴 수 있지만, 첫 화면은 검색 순위 도구보다 콘텐츠 운영 전체를 보여준다. 첫 무료 시작 문구를 실제 `/start` 버튼으로 만든다.

### 4.2 지금 찍은 자료도, 갖고 있던 자료도

“지금 사진·영상 올리기”와 “갖고 있던 사진 맡기기” 두 선택을 보여준다. 매번 새로 촬영해야 한다는 부담을 줄이는 구간이다. 기존 자료 맡기기가 상위 플랜으로 확정되면 해당 조건을 함께 표시한다.

### 4.3 무엇을 만들지도 함께 정합니다

- 목표 검색어: 어디에서 발견되고 싶은지.
- 추천 글감: 무엇을 꾸준히 이야기할지.
- 촬영 안내: 어떤 사진과 영상을 준비하면 좋은지.

세 기능의 관계를 한 화면에서 설명한다. “1년치 글감을 미리 짭니다”의 강점과 계절·시기에 맞는 준비를 유지한다. 실제로 확인된 준비 범위에 맞춰 시각화한다.

### 4.4 자료 하나를 채널에 맞게 준비

블로그·인스타그램, 쇼츠·릴스를 구분해 보여준다. 글·이미지 제작과 영상 편집 준비·완성본 제작·발행을 같은 기능처럼 뭉개지 않는다.
> 연결 가능한 채널과 영상 기능은 계정 상태와 이용 범위에 따라 달라질 수 있습니다.

이 조건문만으로 제공하지 않는 기능을 판매해도 되는 것은 아니다. 앱의 실제 지원, 연결 조건, 플랜별 제공 범위를 먼저 확인한다.

### 4.5 확인하고 예약하거나 자동으로 운영

직접 검토와 자동 승인을 독립적인 가치로 설명한다.
> 처음에는 직접 확인하고, 익숙해지면 정해둔 기준으로 자동 운영할 수 있습니다.

단, 이 문구는 자동 승인이 허용되는 콘텐츠에만 적용한다. 기존 기능 지도 규칙상 영상은 자동 승인 대상이 아니므로 최신 지도와 재대조하며, 영상까지 자동 승인하는 화면이나 문구를 만들지 않는다. 홈페이지 작업 안에서 앱 정책을 바꾸지 않는다.

### 4.6 발행 후 실제 위치를 확인

> 글을 만들었다고 끝내지 않습니다.
> 목표 검색어에서 실제로 보이는 위치를 매일 확인합니다.

> 아직 보이지 않는 검색어는 다음 콘텐츠를 정하는 데 반영합니다.

검색 위치가 낮거나 보이지 않는 검색어가 다음 운영으로 연결되는 흐름이 핵심이다. 확인 주기·대상 채널·반영 방식은 앱 지도와 실제 동작으로 확인한다. 모든 채널에 같은 검색 순위 추적 기능이 있다고 표현하거나 순위 상승을 보장하지 않는다.

### 4.7 일정·이력·문의

기존 부가 기능 카드를 다음 세 묶음으로 정리한다.
- 앞으로 나갈 콘텐츠와 발행된 콘텐츠.
- 올린 사진·영상과 대표 이미지, 자료 확인.
- 문제가 생긴 화면과 사진을 바로 보내는 문의함.

### 4.8 고객 자산과 시작 안내

발행한 콘텐츠가 고객 계정에 남는다는 약속을 유지한다. 입력되지 않는 “가게 이름” 검색창 모양은 명확한 버튼으로 바꾼다.
> 가게 이름만 알려주시면 시작 준비를 도와드립니다.

버튼: **한 달 무료로 시작하기** → `/start`. 무료 대상·조건은 확정된 플랜 정책과 맞춘다.

### 4.9 기존 표현 교정표

| 기존 표현·형태 | 변경 방향 |
|---|---|
| 사진 4장만 올리면 | 사진·영상 몇 개와 짧은 메모를 올리면 |
| 글이 자동으로 완성되고 | 채널에 맞는 콘텐츠를 준비하고 |
| 검색에서 찾아져요 | 발행하고 실제 검색 위치를 확인합니다 |
| 채널에 맞는 콘텐츠 | 블로그·인스타그램과 짧은 영상에 맞는 콘텐츠 — 실제 범위 표시 |
| 노출 방식이 바뀌면 반영 | 검색 변화와 실제 노출 결과를 다음 콘텐츠에 반영 — 동작 확인 필요 |

## 5. 누구나 광고 상세 개선안

### 5.1 가장 먼저 전달할 세 가지

1. **상품으로 광고를 만든다.** 복잡한 광고 화면을 모두 이해하지 않아도 준비를 시작한다.
2. **매출과 광고 성과를 함께 본다.** 여러 화면에서 숫자를 모으는 수고를 줄인다.

- “메타 광고는 어디서 만들어?”

**광고와 매출의 관계:** “광고가 실제 매출로 이어졌는지도 확인” 대신:

서로 다른 자료를 함께 보여주는 것과 광고 효과의 인과관계를 입증하는 것을 구분한다.

**동선:** 기존 데모 `#demo` 목적지, 콘텐츠 앱만 연결된 공통 로그인, 콘텐츠만 설명하는 문의 FAQ를 광고 고객 입장에서 점검한다. 실제 동작은 미검증이므로 구현 시 클릭해서 확인한다.

검색 변화 확인에는 시간이 필요하므로 7일·14일보다 30일이 적합하다는 제안이다. 많은 자료를 맡기는 무료 고객의 비용도 고려한다. 새 제한의 확정 전에는 기존 체험 정책을 임의 변경하지 않는다.

### 7.6 요금 유지 약속

기존 ‘새로운 기능에도 기존 고객은 추가 비용이 없습니다’는 모든 미래 영상 제작까지 무료라는 오해를 만들 수 있다. 제안 문구:
> 이용 중인 플랜의 기본 요금은 그대로 유지됩니다.
> 더 많은 자료 맡기기나 영상 제작이 필요한 경우 상위 플랜을 선택할 수 있습니다.

기존 99,000원 고객의 가격을 유지하고, 이미 사진·영상 맡기기를 제공받는 고객은 현재 권한을 유지하는 방안이다. 실제 고객 권한·계약과 운영 방식을 확인하고 확정한다. 광고에도 상위 플랜이 있는 것처럼 이 문구를 공통 적용하지 않는다. 광고는 §6의 단일 요금·가입 요금 유지 기준을 따른다.

## 8. 디자인·모듈·이미지 원칙

**사용자 지시:** 이미 공들여 만든 디자인의 완성도를 유지한다. 내용에 따라 디자인 변경·추가·이미지 교체는 가능하다. 이미지 없이 모듈로 구현하는 방향을 우선한다. 다만 고객 이해에 이미지가 필요하면 작업자가 직접 만들어 제공한다. 이미지 생성 자체가 필수는 아니다.

보존할 요소: 검정·흰색·파란색의 브랜드 분위기, 기존 글꼴과 큰 제목, 여백, 밝고 어두운 구간의 리듬, 검증된 모듈·움직임. 최신 토큰은 `app/globals.css`, 세부 규칙은 `DESIGN.md`를 따른다. 디자인을 새 템플릿으로 통째로 교체하지 않는다.

선택 순서:
1. 기존 모듈을 재배치하거나 문구·데이터·단계만 바꿔 설명할 수 있는지 확인한다.
2. 필요하면 같은 디자인 언어로 모듈을 확장하거나 새 설명 모듈을 만든다.
3. 실제 기능을 보여줘야 한다면 최신 앱 화면의 핵심 부분을 크게 발췌한다. 화면을 이미지로 고정할지 코드로 재구성할지는 가독성·유지보수·정확성을 보고 결정한다.
4. 사진·일러스트가 있어야 이해되는 구간만 이미지를 제작한다. 작업자가 사용 가능한 이미지 생성 도구로 직접 제작·검수하고 사용자에게 제작을 떠넘기지 않는다. 현재 문서 작성 단계에서는 만들지 않는다.

생성 이미지를 실제 앱 화면·실제 성과·고객 사례의 증거로 사용하지 않는다. 제품 화면·수치는 실제 기능에 근거하고, 예시 데이터는 예시임을 구분한다. 고객 정보는 노출하지 않는다.

한 장면에서 한 행동만 보여준다. 휴대폰 여러 대를 작게 늘어놓지 않는다. 모바일에서도 글자·썸네일이 읽혀야 한다. 전체 화면 축소보다 필요한 카드·구간 확대를 우선한다. PC는 설명과 화면을 좌우 배치할 수 있고, 모바일은 설명 다음 화면이 이어지게 한다. 장식용 일러스트가 기능 설명을 대신하지 않는다.

참고로 전달된 사례: HubSpot의 전체 제품 약속→개별 제품 설명, HubSpot AEO의 부족한 노출 발견→보완 콘텐츠→변화 추적, Buffer의 발행·분석 등 고객 업무 중심 설명과 실제 화면, Shopify·HubSpot의 고객 업무 중심 소개. 이번에는 원문 페이지를 재확인하지 않았다. 실제 디자인 작업에서는 `research-first-redesign` 절차에 따라 공식 자료와 동급 제품·디자인 체계를 조사하고, 이미 공들인 브랜드 스타일에 맞게 적용한다.

## 9. 구현 전 확인·결정할 것

**작업자가 먼저 확인할 것 — 자료에 있는 답을 사용자에게 다시 묻지 않는다.**
- `ngn_upload` 기능 지도에서 직접 업로드·사진 맡기기·채널·영상·자동 승인·글감·촬영 안내·검색 결과 반영을 찾아 what·notes 끝까지 읽고 실제 앱과 대조한다. 특히 영상 자동 승인 금지와 예약 발행을 구분한다.
- 광고 앱 정본에서 챗봇 지원 질문·한도, 보고서 구성, 자동 상품 목록, 연결 지원, 시장 자료 출처를 확인한다.
- 기존 고객 플랜·권한, 영상 편집 결과물과 비용, 무료 체험 처리량을 확인한다.
- 실제 사용할 최신 앱 장면을 확보한다. 콘텐츠의 선택·맡기기·노출·일정 화면과 광고의 제작·성과·질문·상품 목록·보고서·시장 자료가 대상이다.
- 데모·두 앱 로그인·문의·시작 버튼의 실제 목적지와 기능을 확인한다.

**확정이 필요한 정책 — 미확정 부분만 구체적인 선택안으로 제시한다.**
- 콘텐츠 플러스 도입 여부와 기능·수량.
- 스튜디오 정액 공개 또는 영상 상담형, 완성본 월 4편 여부와 추가 편수 가격.
- 기본·플러스 무료 체험 수량, 영상 체험 방식.
- 묶음 상품 도입 여부, 기존 고객 권한 유지의 적용 범위.

광고 199,000원 단일 요금·대행 제외·30일 무료는 이미 확정된 사항이므로 재결정 대상으로 돌리지 않는다. 콘텐츠 요금 미정과 무관하게 공통 디자인 보존·기능 검증·광고 문구 정리는 진행 가능하다.

- 가격·세금·광고비·체험·한도·지원 범위가 모든 페이지에서 일치한다.
- 데모·로그인·문의·시작 버튼이 실제 의도한 곳으로 이동한다.
- PC와 모바일에서 큰 제목·본문·제품 장면이 읽히고 잘림·빈 공간·조작 막힘이 없다. 작은 휴대폰 폭도 확인한다.
