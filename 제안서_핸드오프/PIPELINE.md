# 제안서 제작 파이프라인 — 설계 & 회고

하나금융 웰니스케어 위탁운영 입찰 제안서(2026-07)를 만들며 겪은 시행착오를
다음 제안서 때 반복하지 않으려고 정리한 문서. 실행 규칙 요약은 [CLAUDE.md](CLAUDE.md).

> 자동화가 아니다. 각 단계의 **입력·출력을 고정**해 헤맬 여지를 없애는 "배선"이다.
> 실행자는 사용자가 아니라 **Claude 세션**이다(사용자는 명령줄을 치지 않는다).
> 그래서 규칙을 이 폴더의 CLAUDE.md에 박아 세션이 바뀌어도 유지되게 했다.

## 1. 이번에 실제로 아팠던 지점 (파이프라인이 막아야 할 것)

1. **뭘 달라고 해야 할지 몰랐다.** 입력이 이미지 한 장씩·원고 조각씩 들어옴. 표준 접수 양식 없음.
2. **디자인부터 만들다 갈아엎음(반복).** 소구점·논리를 텍스트로 먼저 확정 안 하고 디자인부터 손댐.
3. **원고 지어내기 위험.** 대표 원고를 토씨 그대로 써야 함(격노 1순위).
4. **이미지 지옥.** EXIF 회전(사진 눕음), 크롭 지점, "그 폴더 어디 있더라".
5. **컨펌 순서 사고.** 렌더 컨펌 전에 PPTX를 뽑아 혼남.
6. **코드 반복 타이핑.** Playwright/python-pptx를 매번 인라인으로.

## 2. 파이프라인 (0 → 5, + 4.5 수정 루프)

```
0. 접수(Intake)      필요한 것 누적 대장. 한 번에 못 받는 전제.       -> 00_intake.md
1. 어필 기획          장별 메시지+소구점 텍스트 + 원고 canonical 고정   -> 01_storyline.md, 원고.md
                     [사용자 컨펌 게이트 — 디자인 전]
2. 자산 정규화        그 장 직전 그 이미지만 정규화(EXIF/리사이즈).      -> imgs/
                     크롭은 CSS object-position (원본 자르지 말 것)
3. 제작              기존 slideNN.html 복사해서 시작.                 -> NN_이름/slideNN.html
4. 렌더·검증          render.py: 폰트/404/오버플로 자동검사             -> renders/slideNN.png
                     -> 모바일 컨펌(thumb 축소본)
4.5 수정 루프         수정 오면: 그 장 [x]->[ ], 재렌더, 재컨펌         -> 순서.md 갱신
5. 빌드·납품          순서.md 게이트 통과 시 build.py + 제출규격 점검    -> 제안서.pptx
```

**핵심 원칙: 1번(텍스트)에서 막고, 4번(렌더)에서 컨펌하고, 5번은 맨 마지막. 수정은 4.5로 돈다.**

## 3. Fable 5 적대적 검토에서 반영한 것

이 설계는 초안(직선 0→5)을 Fable 5에게 적대적으로 검토받아 개정한 것이다. 주요 반영:

- **직선 설계에 수정 루프가 없었다(최대 구멍).** → 4.5 단계 신설. 수정은 첫 빌드보다 급수정 때 사고가 난다.
- **컨펌 게이트가 선언뿐이었다.** → `build.py`가 미컨펌 장을 **코드로 거부**(`순서.md`의 `[ ]`가 있으면 빌드 실패). ROI 최고의 한 수.
- **세션 바뀌면 규칙 증발.** → 규칙을 이 폴더 `CLAUDE.md`에 박음.
- **원고 verbatim 검증이 없었다.** → 원고 canonical 고정 + 4단계에서 **사람이 수동으로** 원문 대조(자동 검사는 아직 없음 — §6 참조).
- **Intake one-shot은 이번 실패의 재현.** → 누적 대장 + "대표에게 보낼 요청 리스트"형.
- **렌더 검증이 빈 화면만 잡았다.** → 폰트 미로드/이미지404/텍스트 오버플로 자동검사 추가.
- **제출규격 미대응(입찰은 규격 미달=실격).** → build.py에 장수·용량 점검 + 표지 규격 사람 확인 안내.

**버린 것(YAGNI):** assets.json 매니페스트(이중 관리 비용), 디자인 토큰 "라이브러리화"(다음 발주처는 하나 그린 아님 — 두 번째 제안서 올 때 theme.css로 추출), 좌표측정 별도 단계.

## 4. manifest.json 대신 순서.md 체크리스트

JSON 수동 편집은 콤마 지뢰. 폴더 자동탐색 단독은 폐기 슬라이드(`_구버전_아카이브`)가 섞이는 함정.
→ `순서.md`: 줄 순서 = 슬라이드 순서, `[x]`/`[ ]` = 컨펌 여부. build.py가 이것만 읽고 미체크면 거부.
사람이 읽기 쉽고 diff도 깔끔하며, 컨펌 게이트를 공짜로 얻는다. 예시: [순서.template.md](순서.template.md).

## 5. 사용자가 직접 만지는 파일은 3개뿐
1. **접수 요청**(00_intake.md) — 대표에게 뭘 요청할지
2. **컨펌** — 모바일에서 렌더 이미지 보고 O/X
3. **수정요청** — 음성·카톡 원문 그대로(정리는 Claude 몫)

나머지(렌더·빌드·정규화)는 Claude 세션이 tools/ 스크립트로 실행한다.

## 6. 다음 제안서 때 할 일 (지금은 안 함)
- 두 번째 제안서가 실제로 오면 이번 CSS를 `theme.css` + `_template.html`로 추출(발주처 CI에 맞춰 색만 교체).
- 필요 시 원고 대조 자동화(슬라이드 텍스트 추출 → 원고.md diff).
- PDF 제출이 필요한 발주처면 render.py `--scale 2` + PNG→PDF 빌드 경로 추가.
