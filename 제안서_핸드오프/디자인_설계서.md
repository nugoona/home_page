## ★★★ 0-A. 대표 PPT(HANA RE:SET) 재구성 규칙 + 시행착오 교훈 (2026-07 — 최우선, 전면 재구성 중)

> 대표(김순재)가 직접 만든 PPT "하나그룹 웰니스 프로그램 제안서 v.1.pptx"(14장, HANA RE:SET 컨셉)로 **전면 재구성**. 기존 운영중심 → 대표의 웰니스 경험 브랜딩. **아래 규칙 위반 = 사장님 반복 격노.** 2장(HANA RE:SET)이 확정 템플릿.

**절대규칙 (매 장 지킬 것):**
1. **내용(텍스트) = 대표 PPT 토씨 그대로.** 추가·삭제·변형·지어내기 절대 금지(반복 위반 지점: 설명문·태그·부제·결론문장 지어내기). 대표에 있는 글자만. 오타만 자동수정(아우름니스→아우름웰니스, Operatonal→Operational). **빠진 내용 없는지 매 장 대조.**
2. **글자 크기 = 대표 pt × 2 = 우리 px, 그대로.** 임의로 키우거나 줄이지 말 것. **작은 글씨 금지**(헤더 소제목도 48px+). 폰트표 = `scratchpad/daepyo_font.txt`.
3. **디자인(위치·시각·이음)만 창의 = 우리 기존 완성도로.** 대표 초안의 디자인(손그림 이음선 등)은 **베끼지 말 것**. 우리 디자인 시스템(§1: 흰배경·그린·헤어라인 격자 카드·좌측 그린바·코너 브래킷·킥커) 완성도로 끌어올린다.
4. **헤더 = 킥커 통일 고정** (전 장 동일 = PPT 기본). 대표 검정 목차박스 X → 우리 킥커(번호박스 + 소제목 크게 + 영문 + 영역배지). 중복 번호(1. (1)) 정리 = **숫자·점·괄호는 내가 편집 가능(융통성)**.
5. **흰 배경 필수 — 다크 톤 금지**(하나금융 밝은 톤). 딥그린은 강조카드 1개만(§9 예외).
6. **매 장 = 대표 스샷 `scratchpad/daepyo_shot/NN.png` Read → 대조하며 제작 → 렌더 → 대표와 다시 대조.** PPT→PNG 변환 = Spire.Presentation(`pip install`, `spire_shot.py`).

**시행착오 교훈 (2장에서 겪음 — 3장부터 반복 금지):**
- ✗ 다크 배경으로 튐 → ✓ **흰 배경 고정**.
- ✗ 대표에 없는 설명·태그·부제 지어냄 → ✓ **대표 텍스트만**.
- ✗ 글자를 대표보다 작게 → ✓ **대표 크기 그대로**(작은글씨 금지, 헤더도 키움).
- ✗ 헤더를 대표 검정박스 그대로(성의없음) → ✓ **우리 킥커로 세련되게 통일**.
- ✗ 이음선을 대표 손그림처럼 점선 수렴(성의없음) / 수식 +·=(더 이상함) → ✓ **3지류→합류점→화살표 굵은 실선 연속, 디테일하게**.
- ✗ **SVG gradient가 세로 직선(bounding box 폭 0)에 렌더 안 됨** → ✓ `gradientUnits="userSpaceOnUse"` + 절대 y좌표. (도식 세로선에 gradient 쓸 때 필수 — 안 그러면 점만 뜨고 선 사라짐)
- ✗ 이음선 노드(점)와 화살표 끊김 → ✓ **합류점→화살표 하나의 연속 path**.
- ✗ 요소 세로중앙정렬로 3R-Return 사이 텅 빔 → ✓ spacer로 헤드-내용 간격, 하단 결론 붙여 종착.
- ✗ 표지 배경을 흰색으로 폐기(다크금지 오적용) → ✓ **표지·클로징 히어로는 딥그린 유지**(다크금지는 본문 슬라이드에만). **글자 크기는 표지 포함 절대 변동 X**(위치만 자율).

## 0. 설계 철학 — 정보의 2계층 (★ 가장 중요, 모든 판단의 기준)

제안서의 모든 내용은 둘 중 하나다:

| 계층 | 정의 | 예시 | 디자인 취급 |
|---|---|---|---|
| **[어필]** | 아우름만의 강점·차별화 = **점수를 따는 것** | 9년 반복운영, 금융권 레퍼런스, BBB0, 투입률 50%, 자체 교육원, 데이터 운영 | **주인공.** 크게·강하게·먼저 보이게 |
| **[정보]** | 공고에 이미 있는 사실 = **발주처가 이미 아는 것** | 2,200명, 42평, 평일13–17시, 1회 2만원, 하루 16명, 베드 6대 | **맥락.** 작게·한 줄·또는 생략 |

**원칙**:
1. "있어도 그만 없어도 그만"인 [정보]는 **과감히 줄이거나 뺀다.** 그 공간을 [어필]에 준다.
2. 한 슬라이드 = **[어필] 주인공 1개** + 근거 2~3 + [정보]는 최소 맥락(작은 띠/각주).
3. [정보]와 [어필]을 **절대 같은 크기로 두지 않는다**(지금까지의 실패 원인).

> 가독성 = "한눈에 뭐가 중요한지 보이는 것". 위계가 그걸 만든다.

## 0.5 작업 파이프라인 (★ 한 장 만드는 순서 — 사장님 확정, 매 장 동일)

> "공지 읽고 → 원고 읽고 → 중요/안중요 구분하고 → 디자인 규칙 지키고" (사장님 지시 그대로)

> **★★★ 디자인보다 "어필 기획"이 먼저다 (사장님 9장 격노 2026-06-30 — 반복수정·시간낭비의 근본 원인). 컴팩션/새 세션에도 이 방식 유지.** HTML 디자인부터 만들지 말 것. 디자인부터 달리면 논리가 뒤따라와, 사장님이 완성품을 보고서야 오류를 발견 → 한 장에 1시간씩 반복 수정. 매 장은 반드시 **① 어필 기획서(소구점+논리+레이아웃 한 줄)를 텍스트로 먼저 제시 → ② 사장님 확인(OK) → ③ 디자인 1회** 순서로 간다(아래 3.5단계). OK 전엔 HTML 착수 금지.

1. **공고 읽기** — 그 장 관련 평가항목·요구사항·공고에 명시된 사실 확인 (`gongo_89bb1fb8.txt`). 평가배점: 품질60(사업능력10·운영능력25·인력25)+가격40.
2. **원고 읽기** — 핸드오프 콘텐츠 브리프에서 그 장 내용 (`CLAUDE_DESIGN_핸드오프.md`). 틀리면 안 되는 사실(인력 5명·투입률50%·풀20+/100·재무 정면해명 등) 준수.
3. **정보 2계층 구분** — [어필](점수 따는 강점=크게/주인공) vs [정보](공고에 이미 있는 사실=작게/띠/생략). §0 기준.
3.5. **★★★ 어필 기획서 작성 → 사장님 확인 [디자인 전 필수, 사장님 2026-06-30].** 디자인(HTML) 만들기 전에 다음을 **텍스트로** 제시해 OK를 받는다:
   - **소구점**: 이 장으로 무엇을 어필하나(한 줄). 모든 장은 어필하려고 만든다 — 소구점 없는 장 금지.
   - **논리**: 왜 설득되나 — 공고 근거 / 대표 전략문서 / 검증 실적 / 내 판단 중 무엇에 기대는지. 논리가 맞아야 한다. (실적·수치는 "자랑"이 아니라 "다리"로: 예 9장 직영샵 ★4.96=검증된 만족 → 하나금융 이식.)
   - **레이아웃 한 줄**: 무엇을 크게(어필)/작게(정보). §0 정보2계층.
   - **여기서 OK 받기 전엔 디자인 착수 금지.** 디자인부터 만들면 논리 오류를 완성품에서야 발견 → 반복수정·시간낭비(9장까지의 문제). 이 단계로 디자인 왕복을 없앤다.
4. **디자인 규칙 적용** — §1.5 공통규칙 + §2 아키타입 + §6 구현 토큰.
5. **렌더 검증(스스로) ★필수** — `python -m http.server 8099`(scratchpad) + Playwright resize(1920×1080)→navigate→screenshot → **반드시 MCP 스크린샷을 Read로 직접 눈으로 보고** 자체 문제를 판단·재수정한 뒤에만 사용자에게 보낸다.
   - **"CSS상 맞다"로 넘기지 말 것.** 코드가 맞아 보여도 렌더 결과가 실제로 맞는지 *이미지로* 확인(정렬·위치·잘림·줄바꿈·가독성·휑함). 어긋나면 스스로 고치고 재렌더 → 다시 확인.
   - **★★★ 심사위원 관점 검증 (사장님 7장 격노 2026-06-30 — "잘림 없음" 형식검증 금지).** 렌더 Read 후 반드시 자문하고, 하나라도 걸리면 고쳐서 재렌더 후에만 전송:
     1) **내가 하나금융 심사위원이면 이게 점수 따는 어필인가?** "그래서 뭐가 차별이지?"가 한눈에 보이나? (정보 나열 ≠ 어필. 어필을 먼저 설계하고 정보는 근거로.)
     2) **프로세스/도식이 그것답나?** 절차면 흐름(연결)이 보이나? 빅넘버면 숫자가 압도하나?
     3) **사진이 잘리거나 맥락 없지 않나?** 무슨 사진인지 한눈에 보이나? 장식용 잘린 컷 금지.
     4) **여백 허허벌판 아닌가? 아이콘 조잡하지 않나? 대시·흐린글씨 없나?**
   - **첫 시도부터 어필 관점으로 설계**(정보 나열 후 어필 붙이기 = 매번 갈아엎는 원인). (실패 사례: 거리 다이어그램 라인이 아이콘 중심과 어긋났는데 "CSS상 중심"이라며 검증 없이 넘겨 사장님께 지적받음)
   - 특히 **요소 정렬(라인↔아이콘 중심), 1080 초과 잘림, 좁아진 영역의 줄바꿈**은 렌더로만 확정된다. 의심되면 해당 부분을 집중해서 본다.
   - 자체 "통과/완료" 판정은 *이미지 확인 후*에만. 확인 안 했으면 "미확인"이라 명시.
6. **사용자 확인** — `SendUserFile`로 전송 → 피드백 반영. OK 받은 뒤에만 다음 장.

> 큰 방향(전체 톤·배경·카피 컨셉)은 **고치기 전에 상의**. 작은 디테일(정렬·간격·색 명도)은 스스로 잡고 보여준다.

## 1. 디자인 언어 (누구나 **실제 코드 실측** 기준 → 색만 아우름 그린)
> 출처: `nugoona/app/globals.css` + `HeroMinimal`·`Comparison`·`SectionHeader` 실측.

- **색 (모노크롬 + 단일 악센트)**: 배경 `#ffffff` / 옅은 블록 `#fafafa`. 텍스트 `#171717`(제목)·`#666`(본문·약)·`#999`(캡션). 헤어라인 `#eaeaea`.
  - **악센트 = 아우름 그린 `#00857A`** (누구나 블루 `#0070f3` 자리). 위험·주의 = 앰버 `#b45309`.
  - **면을 칠하지 않는다.** 강조는 텍스트·숫자 "색"으로만. (유일 예외: 표 헤더 행 `#fafafa` 옅게)
- **모서리**: **전역 직각**(라운드 0). 원형은 작은 dot에만, CTA만 pill.
- **타이포 — 극단적 크기 대비가 위계의 핵심 (★ "기준 없음" 문제의 해답)**:
  | 역할 | 크기(16:9 고정px) | 무게/자간 |
  |---|---|---|
  | 빅넘버·히어로 카피 | **88~120px** | 800, 자간 -0.04em, line 1.08 |
  | 슬라이드 제목 | 40~52px | semibold(600), -0.02em, line 1.15 |
  | 본문 | 18~20px | **light(300)**, line 1.6 |
  | 표·캡션·킥커 | 12~14px | regular~semibold |
  - **주인공(빅넘버/제목)과 본문의 크기 차 = 5~6배.** 이 대비가 "한눈에 중요한 게 보이는" 가독성을 만든다.
- **강조 방식 (누구나 시그니처)**: 문장에서 **핵심 단어·숫자 1~2개만** 그린 + 영문폰트(Inter Tight). 예: "하루 **16명**" → 16만 그린. 문장 전체를 칠하지 않는다.
- **구획 = 헤어라인 (박스 아님)**: `1px #eaeaea` 선으로 구분(상단 보더, 표 행 구분선). 표는 "외곽 얇은 보더 + 행 헤어라인 + 강조열만 악센트색". 라운드 회색 박스 흩뿌리기 **금지**.
- **디테일 (절제된 정교함)**: 작은 dot(5~6px) 커넥터, 크로스헤어 교차점(+), 코너 브래킷(ㄱ자). 미니멀하되 디테일로 완성도를 낸다.
- **여백·정렬**: 큰 여백. 텍스트 폭 **520~760px로 제한**(한 줄 길이↓ = 가독성↑). 섹션 헤더 아래 넉넉히. `word-break: keep-all`(한글 줄바꿈 자연).
- **킥커(영문 라벨)**: Inter Tight, `tracking 0.1em UPPERCASE` (예: TRACK RECORD). 한글 라벨 병기 가능.
- **CTA/버튼**: 높이 52, 검정 채움(`#171717`) 또는 보더. 직각.
- **모션(웹 핸드오프 시만)**: FadeUp 600–800ms, 숫자 CounterUp, ease `[0.16,1,0.3,1]`. (정적 PPT면 생략)

## 1.5 공통 규칙 (★ 2장에서 사장님이 확정 — 전 슬라이드 동일 적용, 위반 금지)

> 2장 제작 중 반복 지적으로 확정된 규칙. 3장 이후 모든 장이 이걸 그대로 따른다.

1. **줄바꿈 = 문장 단위 + 너비 균형.** 본문/설명은 의미(문장) 단위로 `<br>` 줄바꿈하고, 윗줄·아랫줄 너비가 비슷하게. **한 줄로 가능하면 무조건 한 줄.** (어절이 어색하게 다음 줄로 흘러내리는 것 금지 — 예: "남성"만 윗줄 끝에 붙는 것)
2. **줄간격 타이트.** 본문 설명 `line-height 1.42~1.45`, 빅카피 `1.0~1.05`. (느슨한 줄간격 = 정성 없어 보임)
3. **헤어라인/구분선은 위 텍스트와 충분한 간격.** 라벨·텍스트 바로 밑에 선이 붙지 않게 여백 확보.
4. **`─`/`—`/`–`(가로 라인·대시) 전면 금지.**
   - 킥커: 가로 라인 금지 → 번호박스(예 `02`) + 한글 라벨 + EN 라벨로 시작.
   - **텍스트 구분자로 em/en dash 금지** (예 "당기순이익 — 흑자" ✕, "직영 — 청라 30분" ✕, "케어 운영 — 패스트파이브" ✕) → 괄호 `()`·가운뎃점 `·`·쉼표로 대체.
   - **범위 표시도 `~`** ("13~17시", "Lv.1~5", "13:00~17:00"). en dash(`–`)로 범위 쓰지 말 것.
5. **아이콘 = SVG 라인 아이콘만.** viewBox 24, stroke 1.7, round cap. 원/박스 안에 **충분한 패딩**(아이콘이 테두리에 딱 붙지 않게). 이모지·비트맵 금지.
6. **쉼표 = `.comma`** (Georgia serif, 0.72em, 살짝 작게). 큰 타이포의 쉼표에 적용.
7. **강조색 (핵심 단어만, 면 칠 금지):**
   - 흰 배경 강조 = **`#00857A`**(딥그린). 위험·주의 = 앰버 `#b45309`.
   - **다크 영역 강조 = `#00d1b8`(큰 강조: 제목 키워드·빅넘버·badge) / `#00b39e`(라벨·아이콘·보더).** ← 청록빛 `#2fd4bf`는 "마젠타처럼 보이고 안 띔"으로 폐기.
   - **★★ 파스텔/옅은 틴트 면(연그린·연회색 배경 박스) 금지 = 클로드 AI 냄새 (사장님 반복 격노 — 7장에서 또 위반).** `#f5faf8`·`#f1f8f6`·연한 그린 배경으로 구간·카드·강조 박스를 칠하지 말 것. 강조는 **헤어라인 · 점선 테두리 · 좌측 강조선(border-left) · 텍스트 색**으로만. (흰 배경 유지. 면 채움은 딥그린 다크 강조카드 1개 예외만 §9.)
8. **다크 영역 안 본문/캡션 텍스트 = 흰색 계열**(`#fff`~`rgba(255,255,255,.9)`). 연그린(`#9fc4bd`)은 배경에 묻혀 금지.
   - **다크 강조(A안 확정) = 큰 강조(제목 키워드·빅넘버·badge)는 흰색**, 그린은 **라벨·아이콘·dot·badge 테두리** 같은 작은 포인트에만. (딥그린 배경+그린 강조 = 같은 색상환이라 묻힘)
8-1. **★★★ 가독성 = 작을수록 진하게 (클로드 디자인 고질병 · 사장님 4회+ 반복 지적 · 5장에서 또 위반).** 작은 글씨를 연한 회색으로 깔지 말 것.
   - **흰 배경 작은 설명(14~16px) = 색 `#3d3d3d`(=`--body`) + 굵기 최소 `400`.** light(300)+흐린회색 조합 금지(5장 `.rd` "케어 표준과 위생 SOP…"가 light 300+`#5a5f66`이라 안 보임 → 사장님 또 지적).
   - **`--weak`=`#4f4f4f` / `--cap`=`#5f6670`까지만.** 변수 자체를 이보다 흐리게(`#5a5f66`·`#8a9099`·`#8a8f98`) 정의하지 말 것(새 파일 만들 때 :root부터 이 값으로 시작). 밝은 회색 전면 추방.
   - **light(300)은 18px+ 본문에만.** 14~16px 작은 텍스트엔 light 금지(400 이상).
   - **다크 배경 작은 글씨 = 흰색 88%+.** 원칙: "작아서 안 보이면 색·굵기로 보강."
9. **강조 블록은 딥그린 다크 배경 허용**(거점 카드처럼). 단 **슬라이드 전체 배경은 흰색**, 카드 밖은 손대지 않음(하이브리드).
10. **카피 = 직설 평서문.** 억지 대비("안마가 아니라 운영" 류) 금지 — 무엇의 반대인지 층위가 안 맞으면 안 씀. 우리가 약점/리스크를 먼저 들이미는 부정 프레임 금지(긍정형으로).
    - **부정의 부정 금지(헤드라인).** "9년간 끊기지 않았다 / 한 번도 멈추지 않았다" 류 = 나쁜 헤드라인(사장님 2026-06-30). → "9년간 쌓은 경험과 노하우 / 9년째 같은 방식으로 운영" 식 **긍정 단정**으로.
    - **거창·영웅화 금지(헤드라인).** "운영을 책임지는 한 사람" 류 = 손흥민도 아닌데 거창해서 어필 안 됨(사장님 2026-06-30 5장). → "현장 15년, 대표가 운영을 총괄합니다" 식 **담백한 사실**로. 자화자찬·영웅서사 X, 자격·경력 같은 검증 가능한 사실로 신뢰를 만든다.
    - **★★ 헤드라인 카피 = Benefit을 주어로 (사장님 외부검수 비교 후 반성 2026-06-30).** 정보 나열 후 헤드라인 "붙이기" 금지. **고객(하나금융)의 이익을 문장의 주어**로: "데이터가 만드는 품질", "측정하고 개선하는 운영이 이용률과 만족도를 높입니다"(○) vs "쓸수록 좋아지는 데이터 운영"(우리 시점, ✕). **lead=근거/맥락, big=고객 가치.** 금융권 **절제 톤**("멈추지 않는다" ✕ → "운영의 연속성을 지킵니다" ○). **15장 전체를 하나의 흐름**("좋은 운영 시스템")으로 일관. 7~15장 확정 헤드라인 = `확정_헤드라인_7-15.md`(이대로 적용).

### 1.5++ 추가 작업 규칙 (5장에서 사장님 확정 — 2026-06-30, 다음 장 반복 금지)
11. **도트/불릿 정렬 = `align-items:center`** (한 줄 항목). 임의 `transform:translateY(Npx)`로 불릿 위치 맞추지 말 것 — 폰트·줄간격 바뀌면 라인이 어긋난다(사장님 캡처 지적). 여러 줄 항목이면 `align-items:flex-start` + `margin-top:0.5em`로 첫 줄 중앙.
12. **빈 공간은 비율조정/space-between으로 때우지 말 것 = 성의 없음.** 하단 공백이 생기면 **핵심 요소를 제대로 디자인해서 채운다**(5장: 역할흐름을 카드 그리드로 키워 채움). 좌우 높이 비대칭도 콘텐츠로 메운다. "와이어라서"도 공백 방치 금지.
13. **원고 항목이라도 순서·의미가 억지/모호하면 그대로 복붙 금지.** 원고를 *지어내는* 것과 원고를 *맹목 복붙*하는 것은 다르다. 출처는 정직히 밝히되(어디서 왔는지), 어색하면 검토·재구성안을 만들어 사장님 확인받는다. (5장 "역할 흐름" 7단계 순서가 억지 → "대표 직접 관할 영역 4개"로 재구성.)
14. **도식/흐름에는 의미 설명을 붙인다.** 단계·항목만 나열하면 "이게 무슨 말이냐" 지적. 각 항목에 한 줄 설명 + 전체가 무엇인지 리드 문장.
15. **★ 여백 데코 팔레트 (사장님 승인 2026-06-30 — 빈 여백을 데코로 멋지게 채움. SVG 코드 구현 OK, 목업으로 확정됨).** 5종을 **장 성격에 맞게 클로드가 골라** 사용:
    - **C 동심원** = 일반·관할/총괄 영역 (5장 적용). · **S2 코너 브래킷** = 절제·미니멀 필요한 장. · **S3 모눈 그리드** = 공간·도면(예 6장 42평). · **S4 수직 바** = 데이터·KPI·실적(예 9장). · **S5 계단 블록** = 성장·단계·레벨(예 14장 Lv.1~5).
    - 공통 톤: **옅은 선 `#dbe1e6`~`#e6eef0`(stroke 1.3~1.5) + 옅은 면 `#eef5f3` + 그린 포인트 `#00857A` 작은 점/한 요소만.** 카드 **우하단** 등 빈 영역에 `position:absolute; z-index:1`(텍스트는 z-index:2, `overflow:hidden`). 파스텔 면 떡칠 금지(AI슬롭).
    - 후보 시트 파일: `candidate_deco.html`(A/B/C/D), `candidate_deco_c.html`(C1~6), `candidate_deco_sq.html`(S1~6). 채택=C·S2·S3·S4·S5.
    - **★ 적용 방침(사장님 2026-06-30): 여백이 많은 장에만 넣는다. 억지로 넣지 말 것**(콘텐츠가 꽉 차면 생략 OK — 넣어도/안 넣어도 됨). 부채꼴=**C3 부채살 호(Radial Arcs)**. 지칭 용어=코드+이름(C3 부채살, S4 수직바 등).
    - **★★ 데코 위치 = "콘텐츠 블록(표·카드)"의 빈 부분에 넣는다. 헤드라인/킥커 같은 의도적 여백엔 넣지 말 것 (사장님 2026-06-30 명확).** 헤드 영역은 원래 여백이 넓은 게 정상이라 데코 불필요. 진짜 채울 곳 = **표의 우측·하단 빈 칸, 카드 내부 빈 공간** 등 콘텐츠가 듬성한 곳. `position:relative`+`overflow:hidden`인 블록 안에 `position:absolute`로 z-index 낮게(텍스트는 좌측, 데코는 빈 우측). 한 장 다양/통일 자유. 사장님 "○장 표에 C3" 식 지정 가능.
    - **★ 9장 확정 패턴(사장님 정밀 지시): 부채꼴(C3)을 표 각 행 우하단 모서리에 칸칸이.** `.row{position:relative}` + 각 행에 `<svg class="corner" style="position:absolute;right:0;bottom:0">` (우하단 코너 원점 1/4 호 3개 + 코너 그린 점 r2). 모서리에 **딱** 맞춰야 함(right:0 bottom:0). 표·반복 블록에 데코 줄 때 이 "행 모서리 칸칸이" 패턴 재사용.
17. **★ 자기비하 프레임 금지 (사장님 6장 지적 2026-06-30).** 우리 강점/발주처 자산을 스스로 깎아내리지 말 것. "좁은 42평"(42평≈139㎡=충분, 베드6대 OK인데 "좁다" 단정 = 근거없는 약점프레임 + 발주처 제공 공간 폄하). 원고에 그런 표현이 있어도 그대로 쓰지 말고 중립·긍정으로(§13 원고 맹목복붙 금지, §10 부정프레임 금지와 연결).
19. **★ 프로세스/절차는 "흐름"으로 그린다 (사장님 7장 격노 2026-06-30).** 단계를 독립 카드로 나열하면 프로세스가 아님. **번호 노드 + 연결선(타임라인/체인)으로 1→N 흐름을 시각화**한다. 구간 강조는 색으로(예 데이터 구간 그린). "카드 그리드로 때우기" 금지.
20. **★ 아이콘 남발·저품질 금지 (사장님 7장 "그지같은 아이콘").** 의미 연결 약하거나 조잡한 라인 아이콘 박지 말 것. 아이콘이 어설프면 차라리 **번호·타이포·도형 중심**으로. 쓸 거면 통일된 고품질로, 의미가 정확히 맞을 때만.
21. **★★ 도식 비주얼은 제대로 (사장님 7장 2026-06-30 "네모 화살표로 대충하지 마, 필요하면 소스 다운받아").** 손으로 그린 조잡한 SVG path 금지. **검증된 고품질 오픈소스를 가져와 쓴다**: 아이콘=**Lucide**(CDN `https://unpkg.com/lucide@latest/dist/umd/lucide.min.js` → `<i data-lucide="name">` + `lucide.createIcons()`), 필요시 일러스트/다이어그램/패턴도 웹에서 다운로드. 직접 만들 땐 입체·곡선·색으로 정교하게. Playwright 렌더는 JS 실행되므로 Lucide CDN 동작함.
18. **★ 슬라이드 주제의 핵심 시각요소를 빠뜨리지 말 것 (사장님 6장 "성의없다" 지적).** 제목이 "공간"이면 공간(평면·배치)을 보여주고, "데이터"면 화면/그래프를, "인물"이면 사람을. 주제의 본체를 글 카드 나열로 때우면 성의 없어 보인다. 당연한 절차(접수→환복→케어→정비 등 누구나 하는 것)를 [어필]인 양 크게 다루지 말 것 = [정보] 수준은 작게.

- **본문(2~14장)은 실사진만**(스톡/AI 금지). 표지만 스톡 허용. 출처 = `imgs/` 폴더(핸드오프 `제안서_핸드오프/imgs/`에 원본 보관, scratchpad로 복사해 사용).
- **항목 옆 썸네일 방식**: 각 항목(부문·보조 등) = `[텍스트(flex:1)] + [썸네일 묶음(flex:none)]`. 텍스트가 주인공, 사진은 **증거**로 우측 정렬.
  ```
  .sb{ display:flex; gap:30px; align-items:center; }
  .sb .tx{ flex:1; }
  .sb .thumbs{ display:flex; gap:8px; flex:none; }
  .sb .thumbs img{ width:158px; height:106px; object-fit:cover; border:1px solid var(--line); display:block; }
  ```
- **모든 썸네일 사이즈 동일**(예 158×106, 3:2) + `object-fit:cover` → 원본 비율(jpg/png 제각각) 달라도 그리드 정렬됨. **사이즈 들쭉날쭉 금지**(아마추어 느낌).
- **항목당 3장이 기본**(폭 되면). 장수·크기 항목 간 동일하게.
- 이미지 넣으면 **위쪽(빅카피·빅넘버) 공간을 압축**해 썸네일을 키운다(너무 작으면 안 됨).
- **사진 선택은 사장님이 함.** 후보가 모자라면 후보 시트(`candidatesN.html` → 렌더 스크린샷)를 만들어 부문별로 보여주고 파일명으로 선택받는다. 원본 부족 시 `제안서_핸드오프/imgs/`·예전 셀렉 폴더에서 보충.
- **삽입 후 반드시 재검증**: 사진 넣으면 옆/아래 텍스트(특히 좁아진 카드의 desc) **줄바꿈이 깨지지 않았는지 렌더로 재확인**(§1.5-1 위반 주의 — 3장에서 실제로 놓친 적 있음).

### 6.16 이미지 텍스트 오버레이 (2장에서 확정 — 세로 공간 부족 시)
- 항목별 텍스트가 사진과 따로 들어갈 세로 공간이 없으면 **사진 위에 텍스트를 오버레이**한다(높이 = 사진 하나로 압축).
  ```
  .sb-card{ position:relative; overflow:hidden; height:200px; border:1px solid var(--line); }
  .sb-card .ph{ width:100%; height:100%; object-fit:cover; }
  .sb-card .ov{ position:absolute; inset:0; display:flex; flex-direction:column; justify-content:flex-end;
    padding:24px; background:linear-gradient(transparent 24%, rgba(6,24,21,.5) 52%, rgba(6,24,21,.93) 100%); }
  .sb-card .cond{ 13px/600 rgba(255,255,255,.82) } .main{ 20px/700 #fff; .g=#00d1b8 } .note{ 13.5px/300 rgba(255,255,255,.9) }
  ```
- 하단 그라데이션(`transparent→rgba(6,24,21,.93)`)으로 흰 텍스트 가독성 확보. 그린 강조는 다크 위라 `#00d1b8`.
- **구도 조정 = `object-position`**: 얼굴/불필요 부분 빼고 싶으면 사진 교체 없이 `object-position:center 78%`처럼 노출 지점만 이동.
- **높이 1080 고정 주의**: 사진 키우면 `.grid{flex:1}` 같은 게 뒤 요소(info)를 화면 밖으로 밀어낸다. 각 블록 높이를 명시하고 **합이 1080 넘지 않게** 거점카드 패딩·여백을 압축. 렌더로 info 띠까지 보이는지 반드시 확인.
