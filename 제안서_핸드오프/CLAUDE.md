# 제안서 제작 — 작업 규칙 (이 폴더에서 작업 시 반드시 따를 것)

> 이 파일은 세션이 바뀌어도 파이프라인 규칙이 증발하지 않게 하려고 둔다.
> 상세 설계·회고는 [PIPELINE.md](PIPELINE.md). 도구는 [tools/](tools/).

## 절대 규칙 (반복 사고 방지 — 어긴 이력 있음)

1. **원고 지어내기 금지.** 슬라이드 텍스트는 대표 원고를 **토씨 그대로**(오타만 수정). 없는 문구를 만들지 말 것. 원고는 canonical 파일(`원고.md`)로 고정하고, 렌더 검증 시 원문과 **사람이 수동으로 대조**한다(자동 검사 아님 — 도구에 없음).
2. **렌더 → 컨펌 → 빌드 순서.** PPTX(`build.py`)는 **맨 마지막**. 렌더 PNG를 사용자에게 모바일로 보내 O/X 컨펌을 받기 전에는 PPTX를 뽑지 않는다. (컨펌 없이 빌드해서 혼난 이력)
3. **디자인보다 텍스트 먼저.** 새 장은 "이 장이 증명할 단 하나의 메시지 + 소구점 + 논리"를 **텍스트로 먼저** 확정하고 사용자 컨펌을 받은 뒤 디자인한다. 디자인부터 만들다 갈아엎는 게 시간 낭비 1순위.
4. **수정이 오면 그 장의 컨펌은 무효.** "12장만 고쳐줘" 후 재빌드할 때, 수정한 장은 `순서.md`에서 `[x]`를 `[ ]`로 되돌리고 재렌더→재컨펌한다. `build.py`가 미컨펌 장이 있으면 빌드를 거부한다.
5. **`순서.md`의 `[x]`는 사용자 O 컨펌 뒤에만.** Claude가 선제적으로 `[x]`를 치지 말 것 — 그러면 컨펌 게이트가 무력화된다(이번 사고의 재현 경로). 체크는 사용자가 렌더를 보고 OK한 장에만 적용한다.

## 파이프라인 (0 → 5, 상세는 PIPELINE.md)

| 단계 | 요약 | 산출 |
|---|---|---|
| 0 접수 | 필요한 것 **누적 대장**으로. 한 번에 다 못 받는다(이미지·원고는 조각으로 옴). "아직 안 받은 것"을 항상 표시 | `00_intake.md` |
| 1 어필 기획 | 장별 메시지+소구점 텍스트 + 대표원고 canonical 고정 **[컨펌]** | `01_storyline.md`, `원고.md` |
| 2 자산 정규화 | 그 장 만들기 직전 그 이미지만 `normalize_imgs.py`(EXIF 보정·리사이즈). **크롭은 CSS object-position** | `imgs/` |
| 3 제작 | 기존 `slideNN.html` **복사**해서 시작(디자인시스템 재사용). 슬라이드별 폴더 | `NN_이름/slideNN.html` |
| 4 렌더·검증 | `render.py` → 폰트/404/오버플로 자동검사 → 모바일 컨펌 | `renders/slideNN.png` |
| 5 빌드·납품 | `순서.md` 게이트 통과 시 `build.py` → 제출규격 점검 | `제안서.pptx` |

## 도구 사용 (tools/)

**실행 위치 규약**: `render.py`의 `--out`과 `build.py`의 `renders_dir`이 어긋나지 않도록,
**렌더 산출 폴더(`renders/`)와 `순서.md`가 있는 폴더에서 실행**한다(이번 작업은 `디자인_현행/_handoff_클로드디자인/` 기준). `build.py`의 `output`/`renders_dir`/`slides_root`은 상대경로면 `순서.md` 위치 기준으로 해석된다.

```bash
# 렌더(전체/특정 장/고해상). --scale 2는 자동으로 renders_2x/에 저장(컨펌본 보호)
python <tools>/render.py <슬라이드_루트>
python <tools>/render.py <슬라이드_루트> --only 12
python <tools>/render.py <슬라이드_루트> --scale 2
python <tools>/render.py <슬라이드_루트> --thumb 900    # 모바일 컨펌용 축소본

# 이미지 정규화(슬라이드 만들기 직전). src==dst면 거부(원본 보호)
python <tools>/normalize_imgs.py 원본.jpg imgs/edu_hall.jpg --max 1600

# 빌드(순서.md의 모든 장이 [x]여야 통과. 미컨펌·PNG누락·stale·규격미달이면 거부)
python <tools>/build.py 순서.md
```

## 렌더 엔진 주의
- 반드시 `render.py`(Python Playwright, viewport 1920x1080 명시)를 쓴다. MCP 브라우저는 뷰포트를 리셋해 흰 여백/빈 렌더를 만든다.
- 스마트폰 사진은 EXIF 회전 때문에 눕는다 → 항상 `normalize_imgs.py`(exif_transpose) 거친 뒤 사용, 결과를 눈으로 확인.

## 정본·폴더 규약 (중요 — 오해 이력 있음)
- `디자인_현행/` 아래에는 여러 작업 폴더(`slides`, `_handoff_클로드디자인`, `slides_운영백업_*`, `uploads`, `build`, `export`)가 **공존**한다. "디자인_현행 = 구 디자인"이라고 단정하지 말 것.
- **정본이 어느 폴더인지는 `순서.md`가 결정한다.** `slides_root`로 정본 HTML 루트를 지정하고, 그 안의 `slideNN.html`만 렌더·빌드된다.
- `render.py`는 `_`/`.`로 시작하는 폴더(`_구버전_아카이브_*` 등)를 자동 제외하고, 같은 파일명(stem)이 두 곳에 있으면 정본 모호로 **에러 처리**한다.
- ⚠ 새 세션 시작 시 정본 폴더 위치가 불확실하면, 폴더를 훑고 **사용자에게 어느 것이 정본인지 확인**할 것(임의 추정 금지).
